# 03. リスク回避設計（法律・商標・炎上）

**原則：換金できない ・ 実在のものを使わない ・ 表示はデータから自動生成 ・ v1に賭け要素を入れない**

| 領域 | 重さ | 起きうる問題 | 設計での回避策 |
|---|---|---|---|
| 賭博罪 | 重大 | お金を払う→偶然で決まる→換金できる価値、で賭博に近づく | 換金・出金・ユーザー間トレードは一切なし。有償で得た馬や道具は譲渡不可。RMT禁止を規約に明記し検知 |
| 景品表示法（コンプガチャ） | 重大 | 有料ガチャで特定のセットを揃えると別の報酬＝「カード合わせ」で禁止 | 「揃えたら報酬」を有償ガチャの排出物で組まない。設定の自動チェックで弾く。図鑑の達成率には報酬を付けず、実績の組はガチャで出るものを1つでも含めば拒否（下の「図鑑・実績」） |
| 景品表示法（表示） | 重大 | 確率・天井・「確定」の表示が実態と違うと措置命令（実例：0.3%を3%と誤認させた件） | 確率表示と抽選テーブルを同じデータから自動生成。告知文で確率に触れない。自動テストで照合。季節限定の馬は表に印と期間を出し、期間後の天井は恒常へ移す（REQ-BREED-021）。天井ptは失効させず1:1で恒常の交換ptへ移し、移り先・交換先を定義から生成して表示（REQ-GACHA-013）。ステップアップは各段の価格と10枠目の表を表示し「◯倍」「半額」と書かない（REQ-GACHA-014/015）。残り時間は実際の終了時刻があるバナーだけ |
| 景品表示法（総付景品・友達招待） | 要対応 | 招待の報酬が取引に付随すると総付景品（1,000円未満の取引で200円まで） | 報酬は購入を条件にせず、無償コイン・券だけ。1回の付与は ¥200 以下（最小パックの単価で換算）を設定の検証で強制。招待した人への報酬は招待された人の到達でだけ、10人まで（下の「友達招待」） |
| 資金決済法 | 要対応 | 有償コインの未使用残高が基準日（3月末・9月末）に1,000万円超で届出と、残高の半分以上の供託 | 有償・無償コインを分けて管理し、残高を毎日集計。有償から先に消費。ショップに資金決済法の表示 |
| 特定商取引法 | 要対応 | 有料デジタル商品は通信販売。表示義務 | ショップから特商法表記へ。シーズンパスは自動更新・解約方法・金額を購入前に明示 |
| 未成年の課金 | 要対応 | 高額課金トラブル、未成年者取消による返金 | 初回購入時に生年月を確認し、年齢別の月額上限（JOGAの指針に沿って金額決定）。保護者同意 |
| ストア年齢区分 | 予防 | 疑似ギャンブルが入ると13+/18+ | v1は予想・賭けなし。ガチャはストアの質問票どおり申告。確率開示はApple/Googleでも必須 |
| 商標 | 要対応 | タイトル・レース名・団体名 | 実在レース名（「日本ダービー」等）、団体名・ロゴは不使用。レース名・競馬場は架空 |
| 実在の人・馬 | 要対応 | 騎手の名前・顔はパブリシティ権。馬名は判例上違法でないが揉めやすい | 騎手・調教師・馬主・馬は全て架空。命名にNGリスト。実在の馬主の勝負服柄と照合 |
| 他作品との類似 | 予防 | 既存人気作に寄せると叩かれる | 擬人化しない。UI・用語・演出を寄せない |
| AI生成素材 | 要対応 | 既存作や実在馬に似る、規約違反 | 商用可のサービスのみ、生成ログ保存、人が類似チェック。実況音声は実在アナウンサーに寄せない |
| 動物福祉・炎上 | 要対応 | ムチの表現への批判 | ムチ回数制限、痛がる演出なし、故障・予後不良は描かない、引退馬は余生 |
| 公営競技・依存症 | 予防 | 馬券購入へ誘導していると見られる | 馬券・予想サイトへの誘導やアフィリエイトはしない |
| 個人情報・外部送信 | 要対応 | SDKの外部送信は電気通信事業法で公表が必要 | 送信先と目的をプライバシーポリシーで公表。トラッキング許可はチュートリアル後に1回 |
| 海外配信 | 予防 | 有料ガチャ規制国、確率表示義務国 | v1は日本のみ。国ごとにガチャ仕様を切り替えられる作り |

## 種牡馬の貸し借り（REQ-BREED-010〜016）で価値の移転を作らない理由
プレイヤー同士で何かを受け渡す仕組みは、RMT（現金での売買）や、有償で買った価値を他人へ移す経路になりやすい。賭博罪・資金決済法（前払式支払手段の譲渡・換金）・ストア規約の観点で、次のとおり設計している。

- **馬は動かない**：種付けで馬の持ち主は変わらない。譲渡・売買の機能はない（有償ガチャで得た馬も同じ）。生まれた仔は借り手の厩舎で生まれ、譲渡できない。
- **料金は無償コインだけ**：借り手は無償コインでしか払えず（有償コインがあっても使われない）、持ち主は無償コインでしか受け取らない。有償コインは誰にも移らないので、購入額が他人の残高になる経路はない（資金決済法の有償残高・供託の対象も変わらない）。
- **金額と回数に上限**：1回の料金は `feeMax`（既定100）まで、持ち主が1日に受け取れるのは `dailyEarnCap`（既定300）まで、1頭の貸出は1日 `dailyLimitMax` 回、借り手は1日 `borrowPerDay` 回。複数アカウントで無償コインを集める「コイン寄せ」をしても1日の上限を超えて集められない。上限を超えた料金は持ち主に払われず消える（集めるほど損）。リモート設定でもコード上の上限（`STUD_HARD_LIMITS`）は超えられない。
- **購入で付いた無償コインは90日間は料金に使えない**：初回購入ボーナス（無償コインとして付与）は、ストアの返金・取消のときに回収する。回収の前に種付け料で別アカウント（捨てアカウント）へ移されると、返金で現金は戻るのにコインは他人に残る。そのため、購入から90日（`STUD_PURCHASE_HOLD_DAYS`）は、その購入で付いた無償コイン（初回購入ボーナス・サンドボックス分）を種付け料に使えない（支払った後もその額が残高に残っている必要がある）。ガチャ・ショップなど自分の中での利用は従来どおりで、返金時に足りなければ負債になる。返金済みの購入・有償コインで付いたボーナスは対象外。
- **換金・出金なし**：無償コインはゲーム内でしか使えず、現金・他社ポイントに換えられない（全体の原則のまま）。
- **規約**：アカウント・馬・コインの売買（RMT）は禁止と明記し、同じ相手への極端な貸し借りの集中は `stud_breed` KPIイベント（持ち主ID・料金）で監視する。

## 支部の応援スタンプ（REQ-TEAMFEED-*）で文章の投稿を作らない理由
プレイヤー同士のやりとりに自由な文章を入れると、誹謗中傷・個人情報の書き込み・外部サイトや RMT への誘導が起き、その監視と削除の体制（通報の審査・記録・未成年の保護）が要る。支部には次の形だけを用意している。

- **定型スタンプだけ**：絵とラベルはマスターデータで決めたもの。API はスタンプIDしか受け取らず、他の項目があれば拒否する。自動で出るのはレース結果（ランク戦・大会の3着以内）だけ。自由入力のチャットは無い（支部のお知らせは従来どおりリーダー・幹部の短文で NG リスト・URL 禁止。決まった文だけの「定型チャット」は下の §52 の節）。
- **解放にランダムを使わない**：遊んだ回数・シーズンパスの購入・見た目ショップでの直販（決まった価格）だけ。ガチャ・ランダムな報酬から出ないので、コンプガチャや「当たり」の誤認の余地が無い。スタンプは見た目だけで、能力・報酬・換金性は無い。
- **見る人が自分で守れる**：ミュート（その人の項目・応援・通知が消える）と報告（自分の画面から消え、運営のサポート用フラグが付く）。連投は10秒に1回・1日50回まで。
- **退会・削除**：アカウント削除の予定中は投稿できず、削除の処理でその人の項目・応援を全ての支部から消す。

## 支部の定型チャット（REQ-QCHAT-*、protocol §52）で自由入力を作らない理由と、退会・削除の扱い
上の「応援スタンプ」と同じ理由で、支部の会話も**決まった文（定型文）だけ**にする。文の空欄に入るのはサーバーが本人の状態から確かめた値だけ。

- **自由入力なし**：API は定型文の ID とスロットの値（ID）しか受け取らず、他の項目があれば拒否する。表示する文はマスターの日英の組から組み立てる（保存するのは ID だけなので、後から文を直せば過去の投稿の表示も直る）。プレイヤーの文字が入るのは、既に NG 語の確認を通った表示名・馬の名前・カップ名だけ（新しい文字の入口を作らない）。電話番号・URL・外部の連絡先・RMT の誘導を書く場所が無い。
- **文の検証**：定型文は起動時とリモート設定の各版で検証する。共有の賭け言葉リスト（公営競技の連想を避ける）、「倍」「お得」「今だけ」「残りわずか」「通常価格」（有利誤認・偽の急ぎ）、英語の同じ文言チェック、URL を拒否する。購入・ガチャに誘う文は置かない（文の分類は挨拶・応援・支部・レース・誘いだけ）。
- **つきまとい・迷惑の防止**：ブロック（支部フィードのミュートと同じ1つの一覧）は**両方向**に効く：ブロックした人・された人の定型チャットはお互いに見えず、リアクションも名前のスロットもできない（理由は言わない）。連投は1人15秒に1回・1日30回・同じ文の連投禁止・声かけは1日10回まで。通報は §18 の通報で運営のサポート用フラグが付く（Round 17 の通報・ブロック管理 §47 が入ったら、その窓口に同じ項目を渡す）。
- **通知を増やさない**：新しいプッシュの種類は作らない。名前を出された人にだけアクティビティの項目を1件（まとめる）書く。夜間に鳴らす物は無い。
- **支部を抜けた時（決定）**：その人の定型チャットは残し、名前を「元メンバー」にする（`anon`）。文は定型で値も安全なので、仲間の会話の流れを壊さないことを優先する。名簿に居ない人を指す名前のスロットも「元メンバー」になる。個人を結び付ける情報（表示名）は見せないので、退会した人の発言が名前付きで残ることは無い。
- **アカウント削除（決定）**：応援スタンプと同じく、削除の処理でその人の定型チャットを全ての支部（投稿した支部と今の支部）から**消す**。他の人の文の中でその人を指す名前は値を消して「元メンバー」と出す。削除の予約中は投稿できず、アクティビティも書かない。
- **景表法・資金決済法**：定型チャットは何も配らず、何も売らない（コイン・アイテム・解放なし）。

## 友達招待（REQ-INV-001〜012）の景品表示法チェック
招待の報酬は「取引（購入）に付随して提供する経済上の利益」になると景品表示法の**景品類**になり、全員に配るものは**総付景品**として上限がある（告示：取引の価額が1,000円未満なら **200円**、1,000円以上なら取引の価額の**10分の2**）。懸賞（抽選）で配るものは一般懸賞の上限（10万円・売上予定総額の2%等）がかかる。

**設計上の位置づけ**：招待の報酬は購入を条件にしない（招待された人も招待した人も、課金しなくても受け取れる）。招待した人への報酬は「招待された人が無料で遊んで到達したこと」が条件で、招待した人の取引とは結び付かない。このため取引付随性は薄く、景品類に当たらない可能性が高い（オープン懸賞・取引に付随しない利益）。ただし、ゲーム内で有償の取引（コイン購入）をしている利用者がいる以上、**保守的に「総付景品」とみなし、最も低い上限 200円を1回ごとの上限にする**。

| 報酬 | 受け取る人 | 中身 | 円換算（最小パック ¥160/100コイン、`worstYenPerCoin`） | 上限 ¥200 |
|---|---|---|---|---|
| ウェルカムギフト | 招待された人（1回だけ） | スカウト券1枚（恒常ガチャ1回 = 100コイン相当） | ¥160 | 以内 |
| 初心者ミッション完了 | 招待した人（招待された人1人につき1回） | 無償コイン20 | ¥32 | 以内 |
| A級昇級 | 招待した人（同上） | 無償コイン40 | ¥64 | 以内 |
| S級昇級 | 招待した人（同上） | スカウト券1枚 | ¥160 | 以内 |

- 円換算は「その報酬が置き換えるコインを、いちばん割高なパック（¥160で100コイン＝1コイン¥1.6）で買った場合」の金額。無償コイン・券は換金できず譲渡もできないので実際の価値はこれより低いが、上限の確認では最も高く見積もる。
- 招待した人が一生で受け取れる最大は **10人 × ¥256 = ¥2,560 相当**（`maxCountedInvitees` = 10。Round 10 の統合で経済の目標 E2 に合わせて小さく・遅くした、balance-targets 4.10）。1回の付与はどれも ¥200 以下。招待した人への付与は1回ごとが別の到達に対するもので、1つの取引にまとめて付くことはない。
- **コードで止める仕組み**：`progression.invite` の検証（起動時とリモート設定、`inviteProblems`）が、報酬1件ごとの円換算が `INVITE_HARD_LIMITS.maxRewardYen`（200）を超える設定・有償コイン・馬・SR以上確定券・パス経験値など円換算できないものを含む設定を拒否する。人数の上限はコード上20人まで。マイルストーンの種類に「購入」は無い（購入を条件にした瞬間に総付景品の判定が変わるため、作れないようにしている）。
- **抽選にしない**：報酬は確定（ガチャの中身は通常の提供割合どおり。招待で確率は変わらない）。抽選で当たる招待キャンペーンを作る場合は一般懸賞の上限と告知の表示が要るので、別途レビューする。
- **表示**：共有の文と招待画面のどこにも「無料」「◯円相当」「倍」など金額・お得さを強調する表現を入れない（`share.text` はサーバーが作る固定文。報酬の中身は招待画面の表で「無償コイン100」のように事実だけ）。報酬の条件（到達が必要、10人まで、入力は始めてから7日以内、1アカウント1回）を画面と規約に書く。
- **規約**：利用規約に「友達招待」の条項を追加する（キー `terms.invite`、招待画面の「規約」から開く）。内容：報酬の条件と上限、不正（複数アカウント・同じ端末・自動化）の禁止と、不正と判断した場合の報酬の取り消し・停止、報酬は換金・譲渡できないこと、内容の変更・終了。**リリース前の弁護士レビューの対象に追加する**（下の5点に加えて、招待の条項と表示）。
- **個人情報**：インストール ID は端末の乱数で、サーバーにはハッシュだけを保存（同じ端末からの不正の検出のため）。電話帳・SNS の友達一覧は読まない。共有は OS の共有シートだけ。アカウント削除後はハッシュだけ残し、プレイヤーとの結び付きは消す（REQ-INV-010）。プライバシーポリシーにインストール ID のハッシュの利用目的を書く。
- **資金決済法**：報酬はすべて無償（有償コインは出さない）なので、前払式支払手段の未使用残高・供託の計算は変わらない。

## リワード広告（REQ-AD-001〜012）で守ること
- **無償コインだけ**：広告の報酬は無償コイン（とタイムアタックの挑戦回数）だけで、有償コインにはしない。資金決済法の有償残高・供託の計算は変わらない。
- **表示**：報酬は「無償コイン10枚」のように固定額で書き、「倍」「お得」「今だけ」は使わない（設定の検証で弾く）。ガチャの回数を広告で配らない（「無料ガチャ」の表示もしない）。
- **強制しない**：自分で押した時だけ再生。全画面の強制広告は無い。チュートリアル・レース中・負けた直後の結果画面には出さない。
- **未成年・同意**：13歳未満（登録済み）には出さない。成人と分かっていなければパーソナライズしない広告を要求する。iOS の ATT は1回だけ（06 §2.3）。広告SDKの外部送信（送信先・目的・プレイヤーID）はプライバシーポリシーで公表する（電気通信事業法）。
- **報酬の不正**：付与はネットワークの署名付きコールバックだけ。端末からの申告では付与しない。

## 図鑑・実績（REQ-COL-001〜005・REQ-ACH-001〜011）でコンプガチャを作らない理由
**コンプガチャ（カード合わせ）**は、景品表示法の告示（懸賞制限告示 5項）で全面的に禁止されている：「2以上の種類の符票の特定の組合せを提示させる方法」で景品を提供すること。ゲームでは「有償ガチャで出る複数のアイテムをそろえると、別の報酬がもらえる」が典型例（消費者庁 2012年の見解。ガチャの中身そのものが「符票」、そろえた報酬が「景品」にあたる）。図鑑と実績はどちらも「集める・達成する」仕組みなので、次のとおり設計で避けている。

- **図鑑には報酬が無い**：達成率は記録の数字だけで、全部そろえても・一部の組（例：SSR 全種、季節限定の2頭）をそろえても、コイン・アイテム・称号・バッジは何も付かない（`completionRewards: false`、`collectionPercent` などの metric は設定の検証で拒否）。報酬が無ければ「景品」が無いので、カード合わせにならない。
- **実績の「そろえたら報酬」はガチャの中身を含めない**：組み合わせの実績（`metric: collect`）は、組の中に**有償ガチャ（売っている「SR以上確定スカウト券」の抽選表を含む）で出る馬・その馬の固有スキルが1つでもあれば**拒否する（`collectionRewardProblems`）。告示の要件は「2以上」だが、1つでもガチャでしか出ないものを含む組は「ガチャを引けば揃う」誘因になるので、より厳しく線を引いた（既存の `compGachaProblems` は2つ以上で拒否、こちらは1つ以上）。全てのバナーは有償コインで引けるので、プールにある馬は全て「ガチャで出る」扱い。見た目のアイテムも売り物なので組にできない（「買って揃えたら報酬」も作らない）。今ある組は「走ったコース」だけ（コースはガチャでも売り物でもない）。
- **リモート設定で後から壊れない**：バナーのプールを変える版を登録すると、その版のバナーで同じ検査を行う（`validateGacha` の中で実行）。ガチャに入っていなかった馬を新しくプールへ入れて、既存の組がガチャの組に変わる場合も拒否される。
- **実績は遊びだけを数える**：出走・勝利・コース・固有スキルの発動・配合の世代・タイムアタックのメダル・大会・マイ厩舎のいいね・支部の応援。**課金額・購入回数・ガチャの回数・SSRの数を数える実績は作れない**（`FORBIDDEN_METRICS` を専用のエラーで拒否）。ガチャを引くこと自体に報酬を付けると、有償ガチャの購入を景品で促すことになる（取引付随の景品、総付景品の規制の対象にもなりうる）ため。
  - 「固有スキルの発動」「配合の世代」は、馬がガチャ由来でも配合の仔でも、相棒（無料）でも同じように進む「遊んだ回数」で、特定の種類をそろえる条件ではない（どの馬で何回発動したかを問わない）。
- **報酬は無償コインだけ・少額**：1段 ≤ 50コイン（コード上の上限100 = 最小パック換算 ¥160、総付景品の最低の上限 ¥200 以下）、全段の合計 1,235コイン（上限 2,000、コード上 5,000）。有償コイン・馬・券・パスXPは出さない（資金決済法の有償残高・供託は変わらない。抽選も無い＝懸賞にならない）。
- **表示**：未発見の馬はシルエットと「？？？」だけで、図鑑からスカウトへのリンク・「あと◯体でコンプ」「もらえる」の表示は作らない。実績の画面に「課金やガチャの回数では達成しません」と明記する。
- **称号**：実績の段で解放される称号も見た目だけ（能力・報酬・換金性は無い）。買えない。
- **削除・未成年**：削除の予約中は受け取り・解放を止める（REQ-UXS-040）。未成年の購入上限には影響しない（課金に結び付く報酬が無い）。
- **リリース前のレビュー**：弁護士レビューの対象（下記）に、図鑑・実績の画面の文言と `collection.json` の設定の方針を加える。
## 週替わりチャレンジ（REQ-WCH-001〜016）で守ること
- **コンプガチャではない**：3つクリアの週のバッジは見た目だけ（能力・報酬なし、販売なし、全員同じ）。チャレンジは誰でも同じ条件で挑め、達成の条件にも報酬にも**ランダムに提供されるアイテムが一切関わらない**。コンプガチャ（有料のガチャで出る特定の組み合わせをそろえると別の景品が出る）の要件「偶然性で提供されるアイテムをそろえる」を満たさない。報酬に券・ガチャ・馬は入れられない（`weeklyChallengeProblems` が拒否）。
- **景品表示法**：報酬は固定・少額で1つのチャレンジにつき1週1回。無償コインは1回 ≤ 100枚（最も高いパックの単価で ¥160、総付景品の ¥200 未満）、1週 ≤ 150枚。既定の表は配合素材（非売品）だけ。有償コインは付けない（資金決済法：有償・無償の区別）。
- **ランク戦の公平性**：全員クラスBの上限に正規化・スキルなし・調子の揺らぎなし。どのチャレンジにも能力が上限ちょうどの貸し出し馬があり、課金で手に入る馬が無課金より有利にならない。挑戦の回数や条件を緩める商品は作らない。
- **表示**：残り日数は週の終わりの実時刻から（偽の締め切りなし）。「倍」「今だけ」「残りわずか」「お得」「通常価格」を使わない。

## 調教（REQ-TRAIN-001〜014）で守ること
- **課金で強さを買えない**：調教の回数・伸び・素質を増やす商品は無い。伸びに効くアイテム（りんごのおやつ）はデイリーミッションだけで手に入り、商品・コインショップ・パス（無料ラインも。パス＋がレベルを売るため）・イベント報酬・ガチャからは出せない（設定の検証 `trainingProblems` で拒否）。伸びに効かない見た目のアイテムなら確率なしの直販でよい。
- **偶然で価値が決まらない**：結果は決定論（馬の状態・メニュー・タイミングの点数）。乱数はビートの並びだけで、当たり・はずれの抽選は無い（景品表示法の確率表示の対象になるものを作らない）。
- **換金・譲渡なし**：伸びは馬に付くだけで、馬は譲渡できない（全体の原則のまま）。伸びは仔に受け継がれない。
- **動物福祉**：ムチで叩く・痛がる・故障・転倒は描かない。疲れたら休ませる（プールか1日休み）だけ。「疲れ」は調教の効率にだけ効き、レースの結果に影響しない。

## プレゼントボックス（REQ-BOX-001〜014）で守ること
- **資金決済法（有償と無償を分ける）**：ボックスに入るのは無償コインとアイテムだけ。有償コインは入れる欄が型にも無く（`GiftContents`）、運営の配布の入力（`grantSchema`）も無償コインとアイテムしか受けない。有償コインは期限で消えない（ボックスの期限は無償の報酬にだけ付く）。
- **期限の明示**：無償の報酬に受け取り期限（既定30日、お詫び90日、期限なしもある）を付けるので、画面に「受け取り期限は届いてから30日（お詫びは90日）」と、各行に実際の期限（あと◯日・日付）を出す。期限の無いものに期限の表示を付けない。期限を過ぎて受け取れなかった件数は KPI（`gift_expire`）で見る。
- **景品表示法**：ボックスは届け方を変えるだけで、配る額はこれまでの各仕組み（運営の配布の上限・2人承認、大会・イベント・シーズンの報酬表）のまま。ボックスに入れることで額は増えない。「今だけ」「残りわずか」などの言葉、偽の時間制限は使わない（期限は実際の期限だけ）。
- **補填を黙って消さない**：満杯（500件）の時は補填以外で一番期限の近いものを自動で受け取り、それも無ければ上限を超えて入れる（消さない）。アカウント削除では削除の実行と同時にボックスも消え、件数を削除の記録に残す（削除の確認画面の「失うもの」と同じ扱い）。

## ライバル（REQ-RIVAL-001〜016）で守ること
- **報酬は結果で決まる固定の額だけ**：週の勝ち・引き分け・負け・解除それぞれに決まった無償コイン（勝ち 20・他 10、1回 ≤ 100 = ¥160 相当で総付景品の ¥200 未満）。**抽選なし**、**連勝・連続参加の上乗せなし**（「◯週連続で…」の報酬はコンプリートの形に近づくので作らない）。称号は勝った週の**通算**で、見た目だけ。有償コインは付与しない。設定の検証 `rivalProblems` が、上限超え・勝ち ≥ 引き分け ≥ 負けの崩れ・`freeCoins` 以外の報酬（ガチャ券など＝確率のあるもの）を拒否する。
- **ランク戦の公平性**：ライバルはマッチングを変えない（同じ部屋に入りやすくすると、2人で示し合わせた着順の譲り合いでレーティングを動かせるため）。「ライバルと走る」はフレンド部屋の挑戦状で、点にもレーティングにもならない。直接対決の点は確定した結果（合意か検証サービス）だけから付ける。買えるもので点は増えない。
- **個人情報**：ライバルに見せるのは公開プロフィールの写し（表示名・称号・クラス・勝負服）と相棒の馬だけ。レーティングの値・戦績の詳細・フレンド・支部などは出さない。ブロック（支部フィードのミュートと同じ一覧）・オプトアウト・BAN・削除予定の人は組まれず、今週の組はその場で解除（カードも消える）。アカウント削除の手順で登録簿からも消す（`rival`）。
- **通知**：「ライバルが記録を更新」は1日1回まで、プッシュの1日の上限・静かな時間帯・種類（フレンド）の設定の中で。「今すぐ」「残りわずか」などの急かす言葉は使わない（週の残りは「あと◯日」の事実だけ）。

## イベント交換所（REQ-EXCH-001〜012、contracts/protocol.md §30）
- **ポイントは買えない**：イベントポイントはそのイベントのレースでだけ貯まる。商品・ガチャ（有償・無償）・パス・ミッション・運営の付与からは入らず、設定の自動チェック（`eventPointSourceProblems`）が起動時とリモート設定で拒否する。有償コインを払って交換する形でもないので、資金決済法の「前払式支払手段」にもあたらない（換金・譲渡もできない）。
- **ランダムなし・コンプガチャなし**：交換の中身は固定（コイン・素材・券・見た目・名前を決めた馬）。くじ引きの行は定義できず、「全部交換したら報酬」も作れない（スキーマが strict）。そろえる対象がガチャの排出物でないので、カード合わせの形にならない。
- **景品表示法の上限**：無償コインの行は1個 ≤ 100 コイン（最も高い単価で ¥160）・券は1回分（¥160）で、1個ずつ別の付与（各 ≤ ¥200）。10連券・SR以上確定券は交換に出さない。
- **時間の表示は事実だけ**：終了・交換の締切・1日の上限の戻りは定義から計算した実際の時刻。カウントダウンの演出や「残りわずか」「今だけ」は出さない（在庫の「残り 2 / 3」は自分が交換できる数の事実の表示）。
- **黙って消えない**：締切の後、残りのポイントは決めた率（100pt ごとに配合素材1個、切り上げ）で換算し、その率と見込みは締切の前から画面に出す。

## 支部の共同目標（REQ-TGOAL-001〜012）で守ること
- **総付景品の上限**：週の報酬は購入を条件にせず、確定したレース結果（遊び）だけで進む。友達招待と同じく保守的に総付景品とみなし、**1回の付与 ¥200 以下**（最小パックの単価で換算、無償コイン・スカウト券・配合素材だけ）を設定の検証 `teamGoalProblems`（`TEAM_GOAL_HARD_LIMITS.maxRewardYen`）で強制。今の最上段は無償コイン12＋配合素材1（¥20 相当＋非売品。Round 13 の統合で 20 → 12、balance-targets 4.18）。報酬は週に1回（最上段の1つだけ。段ごとに重ねて配らない）。
- **抽選にしない・コンプガチャにしない**：届いた段の決まった報酬を、最低限貢献した支部員全員に配る。ガチャの中身や買える物を「そろえる」条件は無い（数えるのはレース・勝利・タイムアタックの自己ベストだけ）。
- **課金で進まない**：貢献はサーバーが確定したレース結果と検証済みのタイムアタックだけ。クライアントから送る経路も、進める商品も無い（ランク戦の公平性にも触れない：報酬はコインと配合素材で、能力に直接効く物は無い）。
- **表示**：「倍」「今だけ」「残りわずか」などの表現を使わない（締めの日時は事実として「12月21日 4:00 締め」と表示するだけ。カウントダウンで急がせない）。支部名・支部員名はプレイヤーが付けたもので、英語でも訳さない。
- **不正**：1人1日の上限（アカウント全体）で1人や自動化で支部を運べない。隔離・BAN・削除予定のプレイヤーは貢献も受け取りもできず、その人の貢献は支部から消す。支部を移っても同じ週の報酬は1回だけ。

## 購入履歴・コイン履歴・ガチャ履歴（REQ-HIST-001〜014）で守ること
- **資金決済法**：残高は有償・無償を分けて表示し、コインの増減も有償・無償を別のタブで出す（合計だけの表示はしない）。有償コインに有効期限が無いこと・有償から先に使うことを履歴の画面にも書く。
- **特商法・帳簿**：購入の記録は法定の保存期間（`ledgerRetentionDays`、7年）分を本人が見られる。返金・ストアで支払い待ちの状態も文で示す。
- **ガチャの履歴**：直近90日の1回ごとの結果（バナー・引いた馬・使った有償／無償コイン・券・チュートリアル）を本人が見られる。記録は90日で消す（保存の上限）。
- **個人情報**：問い合わせの下書きはプレイヤー id と選んだ行の問い合わせ番号だけ。取引 id・運用者名・台帳の理由文は本人の画面に出さない。削除済みアカウントの匿名の保存記録は、本人・運用コンソールのどちらの履歴からも引けない。
- 履歴の画面の文言（月の上限の書き方「年齢に応じた月額上限」を含む）は、資金決済法表示と合わせて弁護士レビューに回す。

## 殿堂・引退式（REQ-HOF-001〜016）で守ること
- **お金で近道できない**：殿堂入りの条件（勝数・大会優勝・相棒の戦数）は確定したレース結果だけから数える。レアリティ・能力値・購入・アイテムは条件に入らない。報酬の「殿堂の額縁」は非売品（価格0、`hallProblems` が売り物の指定を拒否）で、ショップ・ガチャへの導線は引退式にも殿堂にも置かない。
- **景品**：報酬は見た目の飾り1つだけ、アカウントで1回、抽選なし。コインは出ない（景表法・資金決済法の数え方に入らない）。集める報酬（「◯頭殿堂入りで…」）は作らない（コンプリートの形に近づくため）。
- **個人情報**：友達の殿堂で見せるのは表示名・称号・勝負服と銘板だけ。支部ID・公開範囲・ブロックリストは返さない。見られない理由（友達でない・ブロック・非公開）は言わず、すべて「この殿堂は見られません」（404）。BAN・削除予約中・削除の手順中は写しを置かず、アカウント削除でディレクトリからも消す。
- **名前**：馬の名前・表示名はプレイヤーが入力したもの。英語でも訳さない（NG リストは命名時と同じ。サポートの名前リセットは銘板にも反映）。

## 勝負服エディタ（REQ-SILK-001〜016）で守ること
- **確率なしの直販**：パーツ（特別色・袖・帽子・胴の模様）は1つずつ固定の価格で売る（`kind: "silks_part"`、既存の見た目の直販と同じ購入）。抽選・福袋・セット割・まとめ買いの割引表示は無い。買う前に持っていないパーツのまま試着でき（`POST /v1/silks/preview`）、何をいくらで買うかが先に分かる。
- **資金決済法**：支払いは既存の見た目と同じ（有償コインから先、`paidOnly` の品は有償コインだけ）。購入確認に有償／無償の内訳を出す。遊んで解放するパーツは**配らない**（条件を満たすと持っている扱い）ので、有償・無償のどちらのコインも動かない。
- **コンプガチャ・景品表示法**：パーツを集めると何かもらえる仕組みは無い（実績の `cosmetics` 系の条件も直販品の揃えは検証で拒否のまま）。遊んで解放する条件は実績の段・レース数の固定の条件だけで、ガチャで出るものとは結び付けない。
- **実在の勝負服**：禁止リスト（REQ-ASSET-010）をエディタの組み合わせ全体に広げ、袖や帽子の色を変えただけでは避けられないようにした。リストが後から増えたら表示の時点で既定に置き換え、当たるプリセットは使えない印を付ける。
- **ランク戦の公平性**：見た目だけ。レースの設定・結果ハッシュに入らない。
- **返金**：返金でパーツのアイテムが取り消されたら、装備中の勝負服を既定に戻して1回知らせる（使い続けられない）。プリセットは消さずに使えない印を付ける。

## 実況パック（REQ-CMT-001〜014）で守ること
- **公営競技の賭けを思わせない**：実況の文に馬券・オッズ・配当・払い戻し・的中・万馬券・儲（儲かる・儲け）・賭（賭け）・単勝・複勝・馬連・馬単・三連単・三連複・枠連・ワイド・投票券・予想屋・ギャンブル・本命・大穴・穴馬を使わない。英語も bet / odds / wager / payout / gamble / jackpot / bookmaker / punter / trifecta / exacta / quinella / each-way / favourite / long shot を使わない。実在の馬名・レース名（`ng-names.json`）も使わない。標準の実況（`commentary-ja.json` / `commentary-en.json`）を含めて、起動時（`validateCommentaryPacks`）とテストで検査する。ゲームの「勝ち」は着順の事実だけを言い、お金や利益と結び付けない。
- **入手の形**：標準は全員、1つは実績「出走の記録」1段目（10戦、遊んだ量だけの決まった条件。抽選なし・購入を条件にしない・**売らない**ので円換算の値が無い）、ほかは**決まった値段の直販**（300コイン、有償コインから先に使う。有償限定にする時は有償コインだけ）。抽選・期間限定・セットを揃えた報酬（コンプガチャ）は形として作れない（`acquire.kind` は default / achievement / coins だけ）。買う前に試聴できる（何度でも、サーバーに問い合わせない）。
- **資金決済法**：支払いは見た目の直販と同じ `wallet.spend`（有償・無償を分けて台帳に残す、未精算の返金があれば止める）。パックは持ち物として残り、有償コインに戻らない。無償で配るものに有償コインは含まない。
- **表示**：値段はサーバーのデータからだけ。「倍」「お得」「今だけ」「残りわずか」「通常価格」・残り時間を出さない。確認シートの「購入する」と「やめる」は同じ大きさ。
- **ランク戦の公平性**：実況は端末の中だけで作り、レースの設定・結果・ハッシュ・リプレイに入らない。買えるもので勝率は変わらない。

## マイリプレイ（REQ-MYRP-001〜016）で守ること
- **枠は売らない**：保存は無料で `maxSaved`（20）件まで。購入・パス・広告で増やさない（課金で増える保存枠は「容量を買う」形になり、ランク戦にも関係しないが、やめておく）。上限の文言に購入やショップを出さない。コイン・アイテムは一切動かない（経済の目標なし）。
- **急かさない**：名場面・最近のレースの保存できる期限は本物の日付だけ（「12/30まで保存できます」）。「残りわずか」「今だけ」・カウントダウン・点滅は使わない。
- **個人情報・プライバシー**：保存データに入る他のプレイヤーのプレイヤー ID は `p<slot>` に置き換えて返す（再計算に使わないので結果は同じ）。画面に出すのは馬の名前だけ（観戦と同じ）。公開はプレイヤーが選んだ物だけ、相手はお互いにフレンドの人だけ。ブロック（支部フィードのミュートと同じ一覧）・BAN・退会手続き中は理由を言わず見せない。退会の手続きで R2 の写しも消す（`replays`）。タイトルは表示名と同じ NG 語の確認、URL 不可、翻訳しない。
- **正しさ**：見せるのは確定したレースを端末で再計算し、結果ハッシュが一致した物だけ。ルールセットを引退させた古いレース・再現できないレースは「再生できません」と出し、違うレースを流さない（実況・共有カードも同じ判定の後）。

## 出走前アドバイス（protocol §39、REQ-ADV-003/004/006）
- 競馬を題材にしたゲームなので、**公営競技の予想・賭けに見える表現を使わない**：勝率・確率・オッズ・本命／対抗・穴・単勝・馬券・予想・印（◎○▲△）を、日本語でも英語でも出さない。アドバイスは馬の適性とルールセットの数字（距離・芝ダートの適性外で5%落ちる、得意馬場、スパート区間）から言えることだけで、ゲーム内に賭けの要素は無い。生成する全文を lint（`adviceTextProblems`）でテストする。
- **購入を勧めない**：「◯◯を買えば勝てる」「ガチャで強い馬を」のような導線を作らない（買・購入・課金・ガチャ・スカウト・ショップの語を使わない）。候補は既に持っている馬と、チャレンジなら誰でも使える貸し出し馬だけ。
- **ランク戦の公平性**：無料・全員同じ。プレイヤーが既に見られる情報だけを使い、マッチング前の相手の情報は使わない。アドバイスはレースの設定にも結果にも関わらない。

## フォトモード（REQ-PHOTO-001〜018、contracts/protocol.md §38）で守ること
- **他人のレースに影響しない**：ランク戦・フレンド戦・イベント・大会は走っている途中で止めない（結果画面・リプレイからだけ撮る）。サーバーも `paused` の記録を拒む。写真はレースの状態・結果ハッシュを変えない（端末で計算し直した写しから作る）。
- **景表法・ランダム販売**：写真のフレーム・スタンプは無料・実績で解放・見た目ショップでの決まった価格の直販だけ。ガチャ・ランダムからは出ない。ルック（フィルター）はすべて無料。セットを揃えた報酬は無い（コンプガチャにならない）。能力には影響しない（ランク戦の公平）。
- **表示の言葉**：解放の条件・注意書きは「倍」「お得」「今だけ」「残りわずか」「通常価格」を使わない。プレイヤーのひとことも同じ言葉と、賭けを思わせる言葉（馬券・賭け・オッズ・配当・払戻・的中・予想など）・URL・NG 名を拒む（公営競技への誘導と見られないため）。
- **個人情報**：写真の名札は自分・フレンドの表示名・それ以外は `p<枠>`・CPU（マイリプレイ §37 と同じ伏せ方）。名札をすべて隠す設定がある。共有の文に他人の名前・ID は入れない。サーバーに画像は保存しない（作り直すための小さな記録だけ、最大30件、本人だけが読める、アカウント削除で状態ごと消える）。
- **ひとことは翻訳しない**（プレイヤーが打った文字）。運営が他人に見せる経路は無い（公開・共有はプレイヤーが OS の共有シートで行う）。

## アクティビティ（REQ-ACT-001〜016、contracts/protocol.md §40）で守ること
- **表示とリンクだけ**：一覧はコイン・アイテムを動かさず、受け取りボタンを置かない（プレゼントは「プレゼントボックスへ」のリンクだけ）。受け取りの場所が2つになって二重受け取り・期限の見落としが起きないように、受け取りはプレゼントボックスに1本化する。E番号は無い（経済は変わらない）。
- **急かさない**：文言は起きた事実だけ（「◯◯さんからフレンド申請が届きました」「マイ厩舎に12件のいいねが届きました」）。「今だけ」「残りわずか」・倍・偽の期限は使わない（英語も同じ、`enWordingProblems` のテスト）。未読の数は実際の件数だけで、水増ししない。
- **個人情報・迷惑行為**：ブロック（支部フィードのミュート）した相手からは項目を作らず、あとからブロックした相手の分も消える。退会・BAN の相手は名前を出さず「プレイヤー」と表示する（公開プロフィールが無い・BAN の印）。アカウント削除で一覧ごと消える。
- **同意**：プッシュの設定（種類・静かな時間帯・1日の上限）はプッシュだけに効き、アプリの中の一覧は通知ではないので同意の対象外（06 §3.5 の呼び戻し通知のルールはそのまま）。

## 次にやること（ホームの案内カード、REQ-NEXT-001〜014）で守ること
- **購入を勧めない**：主カードにも、チップにも、ショップ・パスの購入・有償スカウトへのカードは無い（種類ごとに開く画面がコードで決まっていて、設定からも作れない。`feature_unlocked` の対象に `shop`・`season_pass`・`scout` は書けない）。スカウト券は「持っている券で引けます」のチップだけで、主カードにはならない。パスの報酬のカードは受け取り（もう買った物・無料の列）だけで、購入の案内ではない。
- **急かさない**：期限はデータの本物の時刻（プレゼントの期限・交換所が閉まる時刻・週の終わり・調教のセッション）だけを「12月10日 11:59まで」の日付と時刻で出す。カウントダウン・点滅・「今だけ」「残りわずか」「お得」「倍」は使わない（GameChecks・e2e で検査）。毎日の物（ログボ・ミッション）には期限を付けない。交換所は「残ったポイントは、閉まる時に素材になります」と書き、失うような言い方をしない。
- **閉じられる**：どのカードも今日のゲーム日の間は閉じられる（レースのカードだけは常にある受け皿で閉じない）。閉じたことで不利にならない。
- **オンボーディングと競わない**：相棒と2戦目までは「相棒で、本番のコースへ」だけ。コイン・アイテムは動かない。

## シーズンの振り返り（REQ-RECAP-001〜016）で守ること
- **作り話をしない**：数字・名場面はサーバーが確定させたデータだけ（推定・乱数・端末の申告なし）。記録が期間の途中から始まった時は「{date}からの記録です」と書き、足りない分を埋めない。名場面が足りなければ少ないまま出す。
- **お金の話をしない**：コイン・アイテムは動かない（報酬なし、E 番号なし）。購入額・コインの数・ガチャの回数は振り返りに出さない。「倍」「お得」「今だけ」・賭けの言葉（賭け・配当・オッズ）・課金を促す言葉は使わない（サーバーのテストと GameChecks で確認、英語も同じ）。短い版の最後の一言も「次のシーズンも、あなたのペースで。」で、遊ぶこと・買うことを急かさない。
- **プライバシー**：振り返りに他のプレイヤーの名前・ID は入らない（ライバルは勝敗の数、支部は貢献の数だけ）。共有カードは自分の馬の名前と自分の数字だけ、「順位を隠す」でクラス・順位（昇格の名場面も）を外せる。退会でプレイヤーの状態ごと消える。

## プレイヤー主催カップ（REQ-CUP-001〜018）で守ること
- **賞品を付けない**：カップの報酬は見た目だけのトロフィー（プロフィールの棚の数）。コイン・アイテム・ガチャ券・パスの経験値・ミッションの進みは一切付かない（景表法の景品にならない。参加費もない）。主催者が賞品を設定する仕組みは作らない。
- **ランク外**：レーティング・シーズン・ライバルの記録に影響しない（`mode: "cup"` は記録だけ）。購入した物・課金がカップの勝ちやすさに関わる経路もない（馬の能力はそのまま、絆の補正なし）。
- **主催者に有利をなくす**：主催者は他の人の馬を選べず、条件は作った後に変えられない。主催者が決めるのは出走の時刻だけ。
- **入力された文字**：カップ名は表示名と同じ NG 語の確認・URL 不可・制御文字不可で、翻訳しない。結果カード（共有）にはカップ名もほかのプレイヤーの名前も載せない。
- **つきまとい・迷惑の防止**：ミュート（支部フィード・ライバルと同じ一覧）の関係にある人同士は同じカップに入れず、招待も届かない（理由は言わない）。参加コードは推測できない8文字で、照会は1人1時間10回まで。運用はカップを削除（中止）できる（監査ログ）。退会の手続きで主催中のカップは中止、参加の記録は名前を伏せる。
- **急かさない**：開催の時間は本物の時刻だけ。「残りわずか」「今だけ」・カウントダウンは使わない。

## メンテナンス・強制アップデート（REQ-MNT-001〜016、contracts/protocol.md §46）で守ること
- **資金決済法：支払いの済んだ購入を失わない**：メンテナンスの窓の中でも、最低バージョンより古いアプリからでも、購入レシート（`POST /v1/shop/purchase`）とストアのサーバー通知（返金・更新）は必ず受け付けて付与・処理する（`EXEMPT_ROUTES`、テストで確認）。止まるのは新しい購入の始まり（`purchase-intent`）だけ。購入履歴（§33）と退会も止めない。
- **お詫び**：補填は既存のプレゼントボックスの補填（題名「メンテナンスのお詫び」）で、無償コイン・アイテムだけ。有償コインは配らない・プレゼントボックスに入らない。上限と2人ルールは既存のまま（景表法の1回あたりの上限を超えない）。E番号は無い。
- **急かさない**：メンテナンス画面は終了予定の時刻だけを出し、カウントダウン・「まもなく」・「今だけ」などは使わない。窓のメッセージは日本語・英語とも表現の決まり（「倍」「お得」「今だけ」「残りわずか」「通常価格」・公営競技の言葉）を検査してから有効になる。
- **ストアへの誘導**：更新ボタンの宛先は App Store / Google Play の https だけ（サーバーで検査）。外部の決済・配布ページへは誘導しない。
## おすすめフレンド（REQ-FSUG-001〜016、contracts/protocol.md §49）で守ること
- **何も配らない**：フレンドの数・おすすめからの申請に報酬は付けない（E番号なし。招待の報酬は §19 のまま）。数を増やすための仕組みにしない。
- **使う情報（決めたこと）**：もうゲームの中で名前が見えている相手だけ — 同じ支部、フレンド部屋・イベント・大会で同じレースを走った人、マイ厩舎にいいね・応援スタンプをくれた人（アクティビティに名前が出た人）— と、共通のフレンドの**数**（2人以上のときだけ、誰かは言わない）。電話帳・SNS・位置情報・外部の ID は使わない。**ランク戦の相手は使わない**：ランク戦は知らない人と自動で組まれ、観戦・リプレイでも名前を伏せている（§37）ので、名前付きで出すと「当たった人を後から探せる」ことになる。オプトインの設定も置かない。
- **「おすすめに表示しない」の既定はオフ（表示する）**：出る相手はすでに名前を見ている人と共通のフレンドが2人以上いる人だけで、新しく分かるのは「その人がこのゲームで遊んでいる」ことと共通のフレンドの数だけ。1タップでオフにでき、オンの人は誰のおすすめにも出ず、共通のフレンドの橋（その人のフレンド一覧を使うこと）にもならない。**登録した年齢が13歳未満の人は設定に関係なく出さない**（広告の扱いと同じ線）。プライバシーポリシーに「ゲーム内のつながりからフレンドの候補を表示すること、その設定」を書く。
- **迷惑行為**：ブロック（支部フィードのミュート＝1つのブロックの一覧）は両向き — 自分がブロックした人も、自分をブロックした人も出さない。BAN・削除の予約中・退会の人は出さない。おすすめから申請した人は、断られても二度とおすすめに出さない（しつこく申請できない）。申請の上限（同時に送れる申請 `maxOutgoing` など）は今のフレンド申請のまま。おすすめに出ていない人には、この道からは申請できない（id を当てずっぽうに送っても 404、理由は言わない）。
- **急かさない**：理由の行はデータにある事実だけ（「同じ支部」「共通のフレンド3人」）。「今だけ」「残りわずか」・倍・偽の期限は使わない（英語も同じ）。
- **保存**：ブロックの一覧とフレンドの id の写し（カード）はサーバーの中だけで使い、他のプレイヤーには返さない。アカウント削除・BAN・表示しない設定でカードを消す。
## 引き継ぎコード（ID＋パスワード、REQ-TRF-001〜020、Round 19、contracts/protocol.md §54）で守ること
- **資金決済法：有償コインは失われない・動かない**：引き継ぎはアカウント（uid）そのものを新しい端末に移すだけで、コイン・アイテム・購入記録を別のアカウントへ写したり分けたりしない。有償コインの残高・有効期限なし・ストアのレシートとサブスクリプションの紐付けは uid のまま（引き継ぎの後の返金・更新も同じアカウントに効く。テストで確認）。新しい端末の匿名アカウントに有償コインがあれば、引き継ぐ前の確認の画面で**有償コインの枚数を先頭に**出し、「引き継ぎの後に使えなくなる」ことを明示して同意を取る（Apple／Google の切り替えと同じ扱い）。その残高は消さずにそのアカウントに残る（問い合わせで確認できる）。
- **アカウントの売買・譲渡**：IDとパスワードはアカウントを他人に渡す道にもなる。利用規約の「アカウントの譲渡・売買の禁止」の条項に引き継ぎコードを含め、ヘルプ（記事 `transfer_code`）と発行の画面に「人に教えないでください。運営からたずねることはありません」を出す。RMT の通報（§47）と BAN（引き継げない）で対処する。
- **個人情報・セキュリティ**：パスワードは保存しない（PBKDF2 の結果だけ、記録ごとのソルト、反復 100,000 回）。ID とパスワードはログ・KPI・監査に残さない（監査はコードの参照と IP・端末のハッシュの先頭8桁）。ID の有無を教える口を作らない（知らない ID と違うパスワードは同じ答え）。回数の制限とロックで総当たりを防ぐ。IP は塩付きのハッシュでしか数えない（プライバシーポリシーに「不正防止のため、通信元の情報をハッシュにして一時的に使う」ことを書く）。カスタムトークンの鍵は Worker のシークレットだけに置き、入れ替えの手順を決める（docs/ops/deploy.md §9.6）。
- **BAN・退会**：BAN 中のアカウントは引き継げない（新しい端末に逃がさない）。削除の予約中は引き継げない（取り消してから）。退会済みのアカウントのコードは使えない（アカウント削除でコードと監査の行も消す）。
- **急かさない**：期限は事実として表示するだけ（「有効期限：12月11日 12:00まで」）。カウントダウン・「今だけ」などは使わない。作ったパスワードの「この画面でしか表示されません」は安全のための案内で、購入を急かす文ではない。
- **メンテナンス**：認証と同じく、引き継ぎの口はメンテナンスの窓でも止めない（機種変更の途中で閉じ込めない）。経済に触れないので、メンテナンスの目的（購入・レースの整合）とぶつからない。

## 個人データの開示・ダウンロード（REQ-DEX-001〜020、contracts/protocol.md §51）で守ること
**【弁護士レビュー待ち】** 下の方針はリリース前に弁護士の確認を通す（末尾の「リリース前に弁護士レビューを通すもの」に追加）。

- **根拠**：個人情報保護法33条（保有個人データの開示。本人が電磁的記録での提供を指示できる、令和2年改正）。開示の方法として、ゲーム内のリクエスト → 機械で読める JSON と人が読める概要のダウンロードを用意する。海外のプレイヤーには GDPR 15条（アクセス権）・20条（データポータビリティ、構造化され機械で読める形式）の水準で同じものを渡す（v1 の配信は日本のみ、`海外配信` の行）。手数料は取らない（法38条で取れるが、取らない方針）。
- **本人確認**：ログイン中のプレイヤー本人だけがリクエストでき、自分のデータしか出ない（プレイヤー ID はサーバーが認証から決め、リクエストの本文は受け取らない）。メールアドレス・電話番号・身分証は集めない（集めると新しい個人情報が増える）。ダウンロードのリンクは HMAC の署名つき・10分で失効・1人1リクエスト1ファイルに限る。リンクを他人に渡すとその間は開けてしまうので、画面に「リンクを他の人に送らないでください」と書く。**確認事項**：アカウントを乗っ取られた場合の開示のリスクと、ログイン以外の本人確認が要るか。
- **範囲**：プレイヤーの状態のすべてのトップレベルのキーを「出す」か「出さない（理由）」に分類し、新しいキーを分類しないとテストが失敗する（`DEX_CLASSIFICATION`）。出さないもの：重複・処理用の内部記録（再試行の防止・配信待ち・番号のカウンター）、運営のメモ（サポートのフラグ・運営の操作の記録）、他のプレイヤーの情報。JSON の `notIncluded` に「持っているが入れていないもの」と理由を書く（隠していないことが分かるように）。**確認事項**：内部記録・運営のメモを「保有個人データ」に当たらない／法33条2項2号（業務の適正な実施に著しい支障）で不開示にできるか。
- **他のプレイヤーの情報（法33条2項1号）**：フレンドは ID と今の公開の表示名だけ。申請・招待を送ってきた人は数だけ。ライバル・種付けの相手・お知らせを送った人・カップの主催者の ID は入れない。**他のプレイヤーが自分について送った通報**（支部フィードの通報でサポートのフラグに残る「通報した人の ID」）は入れない：通報した人が分かると報復のおそれがあり、第三者の権利利益を害するおそれ（1号）とモデレーションの業務への支障（2号）に当たると考える。**自分が送った通報**（レースの通報：レース・日時・対応済みか）は入れ、対応の内容・担当者は入れない。§47（Round 17 の通報とブロック）の統合で、通報の記録が増えたら同じ線で分類する。**確認事項**：この線引き（自分についての通報の存在・件数だけでも開示すべきか）。
- **アンチチート**：処分の状態・期限・日時は入れ、検知の理由は入れない（検知の方法が分かると不正の回避に使われる、2号）。**確認事項**：処分の理由の開示の要否。
- **資金決済法**：有償コイン・無償コインは残高も履歴も別の一覧で出す（混ぜない）。有償コインのロットは購入の参照と結び付ける。ストアの取引番号は本人のレシートと照合できるように出す。コイン・アイテムは動かない。
- **保存期間**：コインの履歴は法定保存期間（`ledgerRetentionDays`、7年）内の全行、ガチャの記録は 90 日（§33 と同じ窓）、分析イベントは Analytics Engine の保存期間（約90日）。ファイルが大きすぎる時だけ古いコインの履歴を省略し、JSON と概要に「省略した行数・お問い合わせから全件を請求できる」と書く。**確認事項**：省略した場合の残りの開示の方法（お問い合わせで渡す運用）。
- **ファイルの扱い**：非公開の R2（`private/data-export/<playerId>/`）だけに置き、7日で削除（アラームとライフサイクルルールの二重）。運用は状態・時刻・大きさ・監査ログを見られるが、中身・リンクは見られない（管理 API も中身を返さない、閲覧は監査ログに残る）。
- **退会との関係**：削除の予定中（14日の取り消し期間）もダウンロードできる（退会の前に自分のデータを持ち出せる）。削除の実行が始まったら新しいリクエストは受けず、削除の手順で R2 のファイルも消す。削除の後は匿名化した法定の記録だけが残り、プレイヤー ID からは開示できない（§9.4、§33.6 と同じ）。
- **Round 18 統合で決めた線**：§47 の自分が送った通報は「日時・理由・入口・対象の種類・自分の補足・未対応／対応済み」だけを入れ、通報した相手の ID・写し・対応の内容は入れない。§48 のお問い合わせは自分が書いた内容と運営の返信の本文を入れ、返信した運営の ID は入れない。§49 のおすすめは設定と自分が消した人（ブロックの一覧と同じく ID と今の公開名）、最近の対戦相手は数だけ。§53 の馬の目標は入れる。§52 の定型チャットの投稿（支部のフィード、決まった文と選んだ値、`retainDays` 日で消える）は入れない。**確認事項**：定型チャットの投稿を開示の対象に含めるべきか（含める場合は TeamDO から本人の投稿だけを集める）。
- **回数**：7日に1回（準備できたものだけ数える）。法33条は回数の制限を定めていないので、**確認事項**：7日の制限が「開示の請求を不当に制限」しないか（過大な負担の防止として説明できるか、制限中に急ぎの請求が来た場合はお問い合わせで対応する運用）。
- **プライバシーポリシー**：開示の請求の方法（ゲーム内の設定 › プライバシー）、出す範囲と出さない範囲、ファイルの保存期間、分析用 ID（塩つきハッシュ）も保有個人データとして扱うことを書く。訂正・利用停止の請求（法34条・35条）はお問い合わせで受ける（本機能の対象外）。

## 観戦中の応援（REQ-CHEER-001〜016、contracts/protocol.md §55、Round 19）で守ること
- **有料の応援・投げ銭・ギフトは作らない（決めたこと）**：応援は無料で、コイン・アイテム・ポイントを一切使わず、何も配らない（E番号なし）。「応援を買う」「応援で選手にコインが届く」「応援の数に応じた報酬」は、資金決済法（前払式支払手段の他人への移転）・景品表示法・賭博との誤解の面で問題になりうるので、今後も入れない。選手の勝ち負けに賭けるように見える仕組み（応援した馬が勝ったら何かもらえる）も作らない。
- **自由な文字なし**：決まった3つの文（「いけ！」「差せ！」「粘れ！」）だけ。嫌がらせ・個人情報・外部への誘導が書けない。文は共有の賭けの言葉の一覧（`domain/bettingWords.ts`）に当たらない（テスト）。
- **レースに影響しない**：応援は入力・リプレイ・結果の外を通る。ランク戦の公平性（買えるもので勝率が上がらない）に関わらない。遅れのある観戦（10秒）からの応援なので、選手に未来の情報も渡らない。
- **ブロックと匿名**：届くのは数の集計だけで、誰が応援したかは誰にも分からない。ブロック（1つの一覧）は両向きで、ブロックした・された相手の応援は数えない。2秒に1回まで・1秒に1通までで、連打で邪魔できない。選手は表示をオフにできる。
- **保存**：レースごとに残すのは時間の区切りごとの数だけ（id なし）。リプレイのログと同じ保存期間で消える。KPI も1レース1行の数だけ。

## 広告・分析の同意管理（REQ-CNS-001〜020、Round 20、contracts/protocol.md §58）で守ること
**【弁護士レビュー待ち】** 下の方針はリリース前に弁護士の確認を通す（「リリース前に弁護士レビューを通すもの」に追加）。

- **位置づけ**：利用規約・プライバシーポリシーへの同意（REQ-UXS-001）とは**別の同意**として、パーソナライズ広告と分析（KPI）をプレイヤーが選べるようにする。選んだ値・その時のプライバシーポリシーの版・時刻・端末の状態（ATT・CMP）・変更の履歴（50件）をプレイヤーごとにサーバーに残し、同意の証跡にする（KPI `consent_change` も必須のイベントとして残す）。断っても無償コイン・回数・機能は変わらない（サーバーはこの選択を報酬・上限・判定に使わない、テストで確認）。
- **個人情報保護法（APPI）**：分析の ID は塩つきハッシュ（REQ-KPI-005）で、氏名・メールは扱わない。広告 ID（IDFA／広告 ID）は端末の広告 SDK が扱い、サーバーには送らない。**電気通信事業法の外部送信規律（27条の12）**：広告 SDK・分析で端末から外部に送る情報・送信先・目的をプライバシーポリシー（外部送信の公表）に書き、設定 › プライバシー › 広告と分析から2タップ以内で読めるようにする（オプトアウトの手段＝この画面のスイッチ）。日本では分析は既定でオン（プライバシーポリシーの同意の範囲）、パーソナライズ広告は既定でオフ（オプトイン）。**確認事項**：日本で分析を既定オンにすること（公表・オプトアウトで足りるか）、個人関連情報（31条）として広告事業者に渡る場合の第三者提供の同意の要否。
- **GDPR／ePrivacy（EEA）**：配信は日本のみ（v1）だが、UMP（Google の CMP、IAB TCF）の入口をインターフェースの後ろに用意する。`gdprApplies` の端末では、分析は**既定でオフ**（同意が先、ePrivacy 5条3項の端末への保存・読み取り）、パーソナライズ広告は CMP の同意（`obtained`）が無いと効かない。同意の撤回は設定からいつでも、与える時と同じくらい簡単にできる（GDPR 7条3項）。**確認事項**：EEA 配信をする場合の CMP の選定（Google 認定 CMP）、TCF の文字列の保存の要否、分析を「正当な利益」で既定オンにできる範囲（しない方針）。
- **子ども**：既存の年齢の登録（REQ-PUR-002）で13歳未満（EEA では16歳未満、GDPR 8条）を子どもとし、パーソナライズ広告は常にオフ（変えられない、広告リクエストに `tagForChildDirected`）、分析は既定でオフで、保護者の同意（`age.guardianConsent`）がある時だけオンにできる。年齢が分からない・18歳未満はパーソナライズ広告を出さない（REQ-AD-009 のまま）。**確認事項**：COPPA 相当の扱い（v1 は日本のみ）と、13〜15歳の日本のプレイヤーの扱い（今は大人と同じ既定）。
- **Apple ATT（App Store Review Guidelines 5.1.2(i)、App Tracking Transparency）**：トラッキング（他社のアプリ・ウェブとの横断）の前に ATT の許可を取る。事前の画面は**理由の説明だけ**で、報酬で釣らない・煽らない・断った時に機能を減らさない・システムの画面を真似ない（5.1.1(iv) と ATT のガイドライン）。「あとで」では ATT を出さない（OS は1回しか出さないので、許可したい人にだけ出す）。FTUE 中・インストール当日は出さない（06 §2.3）。ATT を断った・制限中はパーソナライズ広告を効かせず、設定の行は端末の設定アプリへの案内にする。`NSUserTrackingUsageDescription` の文言（Codex の handoff）も確認する。**確認事項**：事前の画面の文言（ATT の前の説明として許されるか）、App Privacy（栄養ラベル）の申告内容。
- **必須の記録（分析をオフにしても残すもの）**：KPI のイベントをすべて `essential`／`optional` に分類した（`server/src/domain/kpiConsent.ts`、テストがコードの全イベント名を集めて確認）。必須：購入・返金・パスの更新と状態（資金決済法・返金の記録）、有償コインを使ったかもしれないもの（ガチャ・勝負服のパーツ・実況パックの購入：前払式支払手段の使用の記録）、広告の報酬・拒否（広告ネットワークとの照合・不正対策）、規約の同意・広告と分析の選択、アカウント削除・データの開示（本人の権利の記録）、通報・ブロック・お問い合わせ（安全・サポート）。それ以外（セッション・画面・レースの結果・機能の利用など）は分析がオフの間はサーバーが書かない（クライアントも送らない）。コインの台帳（法定保存）は KPI とは別でいつも残る。**確認事項**：この必須の一覧の線引き（特に広告の報酬・ガチャの記録を「必須」とする根拠の書き方）。
- **再確認**：プライバシーポリシーの版が上がったら、規約の再同意の後、次のホームで事前の画面をもう一度出す（選んでいた値はそのまま効く。勝手に変えない）。**確認事項**：版の変更が「重要な変更」に当たる時に、既存の選択を引き継いでよいか（もう一度同意を取り直すべきか）。
- **開示・削除**：選択の記録は §51 の開示の `account` に全部入る。アカウント削除で消える（KPI の行は §51 と同じ扱い）。
- **閉じない**：同意の画面と API はメンテナンス・強制アップデートで閉じない（撤回はいつでもできる）。

## 通報とブロック（REQ-RPT-001〜020、Round 17、contracts/protocol.md §47）
プレイヤーの名前・リプレイのタイトル・写真のキャプションは NG リストと URL 禁止で確かめているが、すり抜けやふるまい（嫌がらせ・不正の疑い）は機械だけでは止まらない。通報と運営の審査、本人が自分で守れるブロックを用意する。

- **通報だけで罰しない**：通報は運営の審査の列に入るだけ。数が多くても自動で隠す・BAN することはない（レースの通報 REQ-OPS-034 と同じ。通報を武器にした集団の嫌がらせを防ぐ）。対応（問題なし・注意・名前のリセット・キャプション／リプレイを隠す・BAN）は運営が選び、すべて監査ログに残す（誰が・いつ・理由・前後）。BAN は管理者だけ。
- **通報者を守る**：相手のどの画面・API・通知にも通報者・通報の有無を出さない。運営の注意は「お知らせがありました」とだけ書く。
- **端末の言うことを信じない**：通報された文はサーバーが通報を受けた時点で相手の状態から写す（偽の文で他人を陥れられない）。不正の疑いは自分が出たレースだけ。
- **悪用（虚偽の通報）**：1人1日10件・同じ相手に2件まで。運営が「問題なし」とした割合が高い人の通報は並び順で後ろになる（重み 0.5／0.25、5件以上審査された後だけ）。通報そのものは消さない（本当の通報を取りこぼさない）。
- **補足の文**：任意・100文字まで。運営だけが読み、相手にも他のプレイヤーにも見せない（自由な文章が他のプレイヤーに届く経路にはしない、上の「支部の応援スタンプ」と同じ考え方）。
- **個人情報・保存**：KPI には相手の id・補足を入れない。**通報した人がアカウントを削除すると**、その人の通報は通報者を `deleted` に置き換え補足を消して残す（通報された側の審査は続けられる）。**通報された人が削除しても**、その人についての通報は既存の決まり（通報されたレースのリプレイは運営が対応するまで残す REQ-OPS-001a、不正対策の記録と通報の列はアカウント削除で消さない REQ-OPS-034）どおり、運営が閉じるまで残す（BAN 逃れの再登録の確認のため）。閉じた通報は 365 日（`reports.resolvedKeepDays`）で消す。プライバシーポリシーに「通報の内容（通報された名前・文の写し）は審査と不正対策のために保存し、審査後1年で削除する」旨を書く。**リリース前の弁護士レビューの対象に追加する**（保存期間と、退会後も残す理由の書き方）。
- **ブロック**：1つの一覧（支部フィードのミュートと同じ）。相手に知らせない。大会・カップの組み合わせはブロックで変えない（ランク戦・大会の公平のため。相手からの通知だけ止まる）。
