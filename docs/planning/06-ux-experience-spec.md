# 06. UX・オンボーディング・課金体験 仕様（決定版）

作成：2026-11-06　対象：ムチ一閃（リポジトリ muchikeiba）v1 リリース
位置づけ：01〜05 と `docs/spec/requirements.md` を前提に、「何を・どの順で・どう見せるか」を決める。**03（法務）は拘束条件**であり、本書のどの提案も 03 を破らない。破りそうな箇所には「法務」欄で回避策を書いた。

## 0. 結論（要約）

1. **最初の30秒で「ムチで差し切る」を必ず成功させる。** 今のチュートリアルは、ムチ1回だと 8頭中6着に負けたまま命名へ進む（下の §2.2）。勝つまでやり直せる・勝てるよう導く形に作り直す。
2. **乗った馬 ＝ 名付ける馬 ＝ 相棒** にする。今は、名付けた瞬間に裏でガチャを引き、ガチャで出た馬に名前を付けている。乗った馬（アイボウ）とは別の馬で、ガチャの結果も先に分かってしまう。
3. **ホームは初日に4つだけ見せる。** 残りの機能はレース数と日数に応じて順に開く（§4.3）。
4. **レースの手応えを作り込む。** 触覚フィードバック、ムチの手応え、スリップストリームの見える化、スタミナ切れの警告、カメラの改善。今は「掛かり→脚が尽きる→12着」でも理由が画面に出ない。
5. **課金の入口は「初回購入」「スターター」「シーズンパス」の3つに絞る。** それぞれ、気持ちが上がった直後の決まった場面で1回だけ見せる。偽の残り時間は使わない。
6. **シーズンパスは「暦の月＝シーズン」単位の自動更新なしの商品にする。** 今の「購入から30日」ではシーズンとずれる。
7. **ストア審査で必須だが無いもの：** アプリ内でのアカウント削除、特商法・資金決済法の表示画面、Sign in with Apple。リリース前に入れる。
8. 次に作る機能は **マイ厩舎（P1）→ 固有スキル（P1、ランク戦では効果を正規化）** の順。スキルは確率に絡むため表示を慎重に設計する。

## 1. 体験の柱とターゲット

### 1.1 体験の柱
| 柱 | プレイヤーの言葉 | 体験として保証すること | 主な機能 |
|---|---|---|---|
| ① 腕で勝つ（男の夢） | 「最後の直線、俺のムチで差し切った」 | 1レース90秒の中に必ず「判断の瞬間」が3回ある（スタート・位置取り・ムチ）。結果画面で、勝因・敗因が自分の操作で説明される | レース・ランク戦・大会 |
| ② 自分の馬（所有） | 「この馬は俺が名付けて育てた」 | 最初の相棒は一生残る。名前・勝負服・絆・戦績が積み上がり、引退しても血統に残る | 命名・絆・配合・マイ厩舎 |
| ③ 集める（コレクション） | 「次は追込の名馬が欲しい」 | 馬ごとに脚質・適性・（予定の）固有スキルで個性があり、引く理由が「強さ」だけでない | ガチャ・図鑑・季節限定 |
| ④ 競う・見せる（競争と承認） | 「A級に上がった」「厩舎を見に来てくれた」 | 月1回の昇級、週1回の支部戦、大会の観戦。自分の到達点を他人に見せる場所がある | シーズン・支部・大会・観戦・マイ厩舎 |

### 1.2 ターゲット
| 層 | 想定像 | 来る理由 | 残る理由 |
|---|---|---|---|
| 主 | 25〜49歳の男性。競馬・競艇の観戦経験あり、スマホゲームは片手間 | 「騎手として乗る3D対戦」が他にない | 短時間で勝負が決まる、月次の昇級 |
| 副 | 18〜29歳のゲーマー。ウマ娘・ダビスタ経験者 | 配合・血統のやり込み | 血統表、季節限定馬、大会 |
| 副 | 競技寄りのプレイヤー | ランク戦が課金で決まらない | ランキング、タイムアタック、大会 |

### 1.3 誰がなぜ払うか
課金の柱は「勝ちを買う」ではなく **「早く集める・自分らしく飾る・続ける便利さ」**。ランク戦は能力を正規化している（REQ-RATE-003）ので、これを崩す商品は作らない。

| 区分 | 人数の目安（課金者中） | 月額の目安 | 何に払うか | 動機 |
|---|---|---|---|---|
| 無課金 | MAUの94〜96% | ¥0 | 広告視聴（任意・上限あり） | 腕で勝てる、対戦相手として必要な存在 |
| 微課金 | 60% | ¥480〜¥1,500 | スターター、シーズンパス、初回購入 | 「この値段なら損しない」、限定勝負服 |
| 中課金 | 30% | ¥3,000〜¥10,000 | パス＋ピックアップ10連数回、勝負服直販 | 欲しい馬を天井前に取りたい、配合素材 |
| 鯨 | 10% | ¥10,000〜¥50,000（成人のみ） | ピックアップを天井まで、季節限定、厩舎の飾り一式 | 全馬コンプ・血統の完成・見せびらかし |

※ 鯨の天井は低めに置く（正規化で強さが頭打ちのため）。代わりに見た目（勝負服・厩舎）で「見せる価値」を作る。

## 3. コアループとセッション設計

### 3.1 ループ
レース（90秒）→ 報酬（コイン・シーズンpt・パスXP）→ ミッション／ログボ → スカウト（ガチャ）→ 相棒の世話・飾る → レース
長期：引退 → 配合 → 血統 → 次の相棒

### 3.2 セッションの型
| 型 | 時間 | 中身 | 設計上の約束 |
|---|---|---|---|
| 3分 | 通勤・休憩 | 起動 → ログボ（自動）→ ランク戦1回（待ち15秒以内＋90秒）→ 報酬 → 飼い葉1回 → 終了 | ホームからレース開始まで2タップ以内。起動からレース開始まで30秒以内 |
| 10分 | 昼・夜の隙間 | ランク戦3〜4回でデイリーミッション完了、1日の初勝利ボーナス、貯まったコインでスカウト、絆のお世話 | 3戦終わった時点で「今日のミッション完了」をはっきり出す（区切りを作る） |
| 30分 | 夜 | 上に加えて、タイムアタック（ゴースト）、配合、イベント／大会、マイ厩舎の模様替え、支部 | 機能を回る動線を、ホームの「今日やること」リストにまとめる |

### 3.3 スタミナ制はやらない
04 の方針どおり、対戦回数は縛らない。代わりに次の2つで「やめどき」と「来る理由」を作る。
- **1日の初勝利ボーナス**：その日の最初の勝利（1着）を3回まで、無償コインを上乗せ（例 +30、+20、+10）。新規 REQ-UXS-010。経済目標 E1〜E4（balance-targets.md §4）を再計算して上乗せ量を決める。
- **デイリーミッションの完了表示**：3本終わったら「今日の分は完了。明日 0:00（JST）に更新」。

### 3.4 1日のリズム
| 時刻（JST） | 出来事 |
|---|---|
| 0:00（現行） | 日付が変わる（ログボ・ミッション・世話の回数・TAの回数）。**提案：4:00 にずらす**（深夜のプレイ中に日付が変わって報酬を取り損ねるのを防ぐ）。全ての「JSTの日付」を使う処理に関わるので、REQ-UXS-011（P2）で別途検討 |
| 12:07 | シーズンのお知らせの定期実行（REQ-PUSH-006、既存） |
| 21:00 | 大会の標準開始時刻（運営設定）。開始5分前に通知（REQ-TOUR-008、既存） |
| 18:00〜4:00 | ナイター（weather.nightFromHourJst、既存） |

### 3.5 プッシュ通知（既存の種類 season / friends / invites / events の中だけで）
1日の上限は既定5（push.json）→ **2に下げる**（静かな時間帯 22〜8時は維持）。

| 種類 | 通知 | 時期 | 状態 |
|---|---|---|---|

## 6. 画面ごとのUX仕様

共通の約束：
- 横画面固定。セーフエリアの内側に操作を置く。タップ領域は44pt以上（レースの主ボタンは88pt以上）。

### 7.1 固有スキル（次の予定）
**狙い**：馬ごとの個性を「脚質・適性」より一段強くし、ピックアップの理由を作る。ただしランク戦が課金で決まらないこと（柱①）を守る。

| 項目 | 方針 |
|---|---|
| 効果の種類 | 発動条件（例：直線で前に2頭以内／コーナーで内ラチ沿い／残り脚30%以下）＋効果（一定tickの目標速度＋◯‰、脚の消費−◯‰など）。全て整数‰ |
| 公平性 | ランク戦では効果量をクラス上限で頭打ち（正規化と同じ考え）。1頭1スキル、R/SR/SSR で効果量の差は小さく（例 SSR は発動条件が広いだけ）。balance-targets に R9「スキル持ちSSRの勝率 ÷ 同能力のスキルなし」≤1.15 を追加 |
| 確率 | 発動は条件だけで決まり、**乱数を使わない**（決定論・確率表示の手間を避ける）。乱数を使うなら発動率をデータから表示 |

### 7.4 ガチャの演出・天井表示・開催カレンダー（Round 9 で実装、7位）
**狙い**：「欲しい馬が分かり、引く前に確率・天井が分かる」（§6.5）を守ったまま、期間限定のピックアップとステップアップで引く理由を作る。偽の急かしは使わない。

| 項目 | 決めたこと |
|---|---|
| 開催カレンダー | バナーは `startDay`〜`endDay`（ゲーム日。日付の切り替え時刻に開閉）で書く。予告は3日前（季節限定は7日前）から。一覧は開催中と予告中だけで、並びは「終わりがあるもの（早く終わる順）→ 常設（恒常は最後）→ 予告」。予告前のバナーは提供割合も出さない（日程を漏らさない） |
| 境目 | 引けるかはその取引でサーバーが読んだ時刻で決まる（終了の1 ms 前は引ける、終了の時刻からは `BANNER_CLOSED`、メッセージに終了時刻）。端末の残り時間がずれていても、サーバーが断り一覧を取り直す |
| 残り時間 | 実際の終了時刻があるバナーだけ。1日より多ければ「残り◯日◯時間」、最後の1日は時:分:秒。期間は「11月30日 23:59まで」（終わりの1分前を表示）。常設は「常設」で時計なし |
| 天井の表示 | バナーごとに「交換pt 37 / 100（あと63回・6,300コイン）」とメーター。交換先（所持の印）と「えらんで交換・抽選なし」。閉じるグループは移り先の文言をそのまま出す |
| 天井ptの持ち越し | **期間が終わっても失効しない**。残りの交換ptは恒常（`standard`）の交換ptへ1:1で移り、恒常の交換先（4頭）から選んで交換できる（抽選ではない）。日本のゲームで一般的な「交換ptの引き継ぎ・別の交換への変換」に合わせ、失効させる案は採らない（期間終了直前の駆け込みを煽らない・消費者の不利益を避ける）。文言はデータから生成し、天井の表示・提供割合・季節限定の注意書きで同じものを出す。グループは最後のバナーと同時に閉じ（使えない期間を作らない）、閉じないグループには常設のバナーが要る（設定の検証） |
| ステップアップ | `stepup_paid`：有償のみ・10連のみ、500 / 1,000 / 1,000 / 1,000 / 1,000、5段目の10枠目はSSRの表（必ず）、その後1段目へ。各段の価格と10枠目の表を提供割合に出す。「半額」「◯倍」とは書かず、価格と中身だけ |
| めくり | 1枚ずつ。裏面はレア度の光の色＋形（◆ / ★ / ★★）で、めくると色＋形＋文字＋枠の模様。低いレア度から、最も高いものを最後に（同じレア度はサーバーの順）。「すべてめくる」1タップで一覧へ |
| 一覧 | 全ての結果を必ず出す（スキップしても隠れない）。高いレア度から。新規は「NEW」、ダブりは「ダブり → 覚醒素材 +20」（正確な量）、合計「新規 7頭・ダブり 3頭（覚醒素材 +25）」、使ったコイン（有償／無償）、ステップアップの次の段、交換pt |
| 文言の検査 | 生成する文言（提供割合・一覧・天井）に「倍」「通常価格」「今だけ」「残りわずか」「お得」が無いことをテストで確かめる |

## 通報とブロック（REQ-RPT-001〜020、contracts/protocol.md §47、Round 17）
- **入口**：ほかのプレイヤーが見える場所（プロフィール・フレンド一覧・支部フィード・マイ厩舎の訪問・殿堂の訪問・リプレイ／写真・カップのロビー）に「通報する」。押すと右からのシート（通報シート）。メニューの奥に隠さないが、目立たせもしない（小さな枠線のボタン、色は他の補助ボタンと同じ）。
- **通報シート**：1行目に「運営が内容を確認します。通報したことは相手に知らされません。」。対象（名前・タイトル・キャプションはプレイヤーが書いたまま、訳さない）、理由（対象に合うものだけ、2列のボタン）、補足（任意、文字数のカウンター「12/100」、超えたら送れない）、「この人をブロックする」（初期はオフ）、送る（1つだけの CTA、理由を選ぶまで押せない、送信中は押せない）。結果は「通報を受け付けました。ご協力ありがとうございます」だけで、まとめられたか・何人が通報したかは出さない。今日の上限に達したら「今日はこれ以上通報できません。4:00に戻ります」。
- **通報とブロック（その他 › 通報とブロック）**：ブロック中の人の一覧（今の名前、退会した人は「プレイヤー」）と「ブロック解除」、右に「ブロックするとどうなる？」（アクティビティ・支部フィード・ライバル・マイ厩舎・殿堂・リプレイ・カップの7行、サーバーの文）。解除は確認のダイアログ（「ブロックを解除しますか？」・相手には知らされない）を挟む。ブロックは1回のタップで良い（取り消せるので）。
- **運営からのお願い**：運営が注意した時はアクティビティに「運営からのお願い」が1件（誰が通報したかは書かない）。押すと「通報とブロック」へ。
- **文字の大きさ・英語**：シートと一覧は特大・英語でもはみ出さない（`test/a11y-flow.cjs`・`test/en-flow.cjs`）。
## 補足（Round 17）：メンテナンス・強制アップデート（REQ-MNT-*、contracts/protocol.md §46）
- **オフラインとメンテナンスは別の画面**：応答が無い＝オフラインの帯（練習レースは遊べる）、503 `MAINTENANCE`＝メンテナンス画面、426＝更新が必要な画面。メンテナンス・更新の画面の上にオフラインの帯は出さない。
- **全部止まる時だけ全画面**：範囲が「すべて」の窓はメンテナンス画面（写真の背景・パネル1枚・主ボタン「再読み込み »」1つ）。機能だけ止まる窓は、その機能を開いた時の小さな案内（「この機能はメンテナンス中です」「ほかの機能はいつもどおり遊べます。」）で、ほかは普段どおり遊べる。
- **時刻だけ、急かさない**：終了予定（日本時間）を大きな数字で1つ。カウントダウン・進捗バー・点滅は使わない。予定の窓は新着情報（お知らせ）から開ける。
- **更新**：最低より古い＝閉じられない更新画面（「ストアへ »」）。推奨より古い＝ホームのシート1回（「あとで」で同じバージョンでは二度と出ない）。
- 文字の大きさ（§11）・動きを減らすに従う（a11y の通しで3画面とも特大の日英ではみ出し0件）。

## 補足（Round 20）：レビュー依頼のタイミング（REQ-REV-*、contracts/protocol.md §59）
- 頼むのはうれしい瞬間の画面（初勝利の結果・大会の表彰・殿堂入りの式・目標の物語の印）を**閉じてホームに戻った所**だけ。演出・レースの途中・購入の途中には出さない。負け・購入・エラー・返金・メンテナンスのお知らせの直後、FTUE の途中は出さない。1セッション1回まで。
- 出すのは OS の標準のレビューのシートだけ（独自の★の画面は作らない）。前置きの質問（「ムチ一閃を楽しんでいますか？」はい／いまいち、閉じる）は運用の設定で iOS だけ ON にできる（既定 OFF、Android は不可）。シートはムチ一閃の見た目（紺の半透明の面・水色の小さな見出し）で、2つの答えは同じ大きさの副ボタン（水色の主ボタン「»」は使わない＝はいを目立たせない）。いまいち → お問い合わせ（その他）。文字の大きさ（§11）に従う。
- レビューには何も配らない。シートにもどこにも報酬・コイン・★の数の誘導を書かない。
