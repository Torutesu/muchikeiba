# 経済の基準の見直し（economy）— 品質パス3

品質パス3の4本のうち「経済」。品質パス2（docs/quality/ranked.md §3.3・§6-1）で、経済の目標 E1（無課金・毎日遊ぶ人の引ける回数/月、40〜65）が**実際のランク戦では成り立っていない**ことが分かった。シミュレーションは着順を1〜12の一様に引いていたが、ランク戦のハーネスが測った「平均的な人」の着順で同じ人を90日走らせると E1 は **76.4**（E2 3.22 SSR/月・天井 36日目）。オーナーの決定：E1 を実際の着順で測り（40〜65）、ランク戦の着順コインと初勝利ボーナスを下げて範囲に戻す（目安 −15%）。

- ブランチ：`quality/economy`
- 触ったところ：マスター（`progression.raceFreeCoinsByPlace.ranked`・`progression.firstWinBonus.freeCoinsByWin`）、経済シミュレーション（`server/src/sim/economy.ts` の `rankedPlacesPersona`・`rankedRulesetVersion`）、`npm run economy`（実際の着順の E1 を最初の表に）、`server/test/economy.test.ts`（主の E1〜E3 を実際の着順で、W8 を 40〜65 に、腕の差が報酬に出るかの検査）、`contracts/ranked-fields.sample.json`（`coinsByPlace` だけ、`npm run gen:ranked-sample`）、文書。エンジン・ルールセット・検証サーバー・ゴールデン・クライアントのコードは変えていない。

## 0. 結論

1. **−15% では足りなかった。** 着順コインと初勝利ボーナスを15%下げると（34/21/15/12/9/8/6/5/4/3/3/3・25/17/8）実際の着順の E1 は 69.8・E2 3.11 で、どちらも目標の外。品質パス2の「目安 −15%」は、平均的な人のランク戦のコイン（1日 約95＋初勝利 26）を少なく見積もっていた（E1 は無償コイン 1枚/日 ≒ 0.3回/月で動くので、76.4 → 62 には 1日 約48枚 減らす必要がある）。
2. **採用：着順コイン 約 −34%、初勝利ボーナス 30/20/10 → 20/10/5。** 実際の着順の E1 は **76.4 → 62.0**（E2 3.22 → 2.56・天井 36 → 44日目）。目標 40〜65 の中で上限から 3.0 の余裕（品質パス2までの 64.2 / 65 の 0.8 より広い）。
3. **腕の差はそのまま残した。** 表は全体をほぼ同じ割合で下げた（1着/2着の比 1.60 → 1.63）ので、C級で上手い人のコイン/レースは平均的な人の 1.79倍（変更前 1.81倍）。上手い人の1日の無償コインは平均的な人の 1.32倍（変更前 1.39倍、初勝利ボーナスを下げた分だけ縮んだ）。
4. **見た目・文言はコードの変更なし**：結果画面の「無償コイン +N（初勝利ボーナス +N を含む）」、ホームの「初勝利ボーナス 残りN回（次はNコイン）」、ミッションのシートはサーバーの値をそのまま出す。コインの額を書いた文言（ヘルプ・ヒント・英語）は無かった。
5. **出し方**：リモート設定だけで出せる（Worker・アプリの出し直しなし）。ゲーム日の切り替え（4:00）の直後に有効化し、お知らせを先に出す（docs/ops/deploy.md §7.1 の行）。

## 1. 何が弱かったか（監査）

| # | 弱いところ | なぜ困るか（楽しさ・続ける・課金） |
|---|---|---|
| 1 | E1 の前提「平均的な人＝一様な着順」が実際の場と合わない。平均的な人は初心者マッチで 50% 勝ち、C級の ramp で 22%、B級・A級の30日目の馬で 17〜20% 勝つ（一様なら 8.3%） | 設計より 19% 多く引け、SSR が月 3.2頭（目標 ≤2.8）。馬の価値が下がり、天井（36日目）も早すぎる。パスの比 E5 も実際は 1.22 より小さく見える |
| 2 | 上手い人は E1 100.9・SSR 4.44/月・天井 23日目 | 毎日遊ぶ上手い人ほど「スカウトするものが無い」が早く来る。長く続ける動機が減る |
| 3 | E1 の余裕が 0.8（64.2 / 65） | 他の機能が無償コインを1枚も足せない（騎手の道は 0 コインで出した、balance-targets 4.20）。どの調整も E1 で詰まる |
| 4 | 一様の E1 が主の目標で、実際の着順の E1 は「見張るだけ」（W8 40〜77） | 場（`rankedField`）を変えると経済がずれても誰も気づかない |

強いモバイルのレースゲーム・対戦ゲームに共通するやり方（一般論）：報酬の基準は**実際のプレイの分布**で決め、勝ちやすくした分は「1勝の額」で返す。腕の差（勝ち）には払い続けるが、1日の上限に近い固定の報酬（初勝利・デイリー）は小さくして、毎日の稼ぎの大半を「遊んだ回数」に結び付ける。

## 6. 危険と、オーナーに決めてほしいこと

1. **−34% は目安の −15% の倍以上**。−15% では E1・E2・E3 が目標の外（§2 の A）。1日の無償コインは平均的な人で −44枚（218 → 174）。下げ幅を小さくしたいなら、目標 E1 の上限側の余裕（3.0）を削る C 案（64.2）がある。
2. **既存のプレイヤーへの見え方**：1着の額が 40 → 26 になる。勝ちの手ごたえは結果画面の演出・順位・シーズンポイントで保ち、額の変更はお知らせで正直に出す。D7 と1日のレース数を出した後1週間見る（`docs/ops/kpi-queries.md`）。
3. **連打する人の E1 38.7**（40 未満）。E1 の目標は平均的な人なので受け入れたが、「誰でも週1回10連」を連打する人にも当てはめるなら、尻尾（9〜12着）を 4 に戻す案（見積もり：連打する人で1日 +3枚ほど、平均的な人の E1 +0.5ほど）がある。
4. **一様の E1 は 55.3 に下がる**。E5（パス ÷ 無課金）などの比は分母が小さくなって少し上がる（§3.3）。
