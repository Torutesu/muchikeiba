### 1.2 行き止まり・重複・意味の薄い報酬（重い順）

| # | 見つけたこと | なぜ楽しさ・継続・課金に効くか |
|---|---|---|
| 1 | **初心者ミッション10段（最後は10連スカウト券）とシーズンミッション5本（パスXP 900＝9段分）がサーバーにあるのに、ムチ一閃 UI のどこにも出ていない**。次にやることの `missions_claim` もデイリーしか数えない。7日目の状態で初心者 0/10・受け取れる報酬7件が眠っていた | いちばん強い「明日も来る理由」（10連券）が見えない。経済のシミュレーションは受け取る前提で数えているので、実プレイヤーは設計より貧しい |

| 3 | シーズン枠は「昇級ラインに到達」で止まる。昇級が月末に決まること、次のクラスで何が変わるか、各クラスの報酬が分からない。いまのペースの目安も無い | 7日目でラインに届いた人に、残り3週間の目的が無い |
| 4 | ログボは自動で受け取りトーストだけ。**明日の報酬（初心者2日目＝繁殖牝馬）を一度も見せない** | 1日目→2日目の一番大事な橋が見えない |
| 5 | 「勝つ」に3回払う：初勝利ボーナス（30/20/10）・デイリー「1着」30・シーズン「5勝」。表示はミッションのシートの1行だけ | 目標が多く見えるのに、行動は1つ |
| 6 | パスの無料ライン＝**全30段が同じ「無償コイン10枚」**。次にやることの `pass_claim` は、主ボタンが購入の画面へ連れていく | 受け取りが作業になる。無料プレイヤーを購入画面に送るのは押し付けに見える |

| 8 | ミッションのシートは「受け取る」ボタンが初勝利の行に重なる | 受け取りの瞬間が雑 |

### 1.3 ジャンルの強いゲームがうまくやっていること（仕組みとしての一般論）

- 「今日の分」を1つの集合にして、1つの数字（3/5）と1回の完了の瞬間を作る。
- 短期・中期・長期の目標を同じ画面で縦に並べ、いつも「次の一段」が見える。
- 報酬を中心の遊び（ここでは馬）に結びつけ、何に効くかを一言で言う。
- ランクは「上がると何が変わるか」を数字で見せる。課金で上がらないことを明言する。
- 明日の報酬は事実として先に見せる（カウントダウンや煽りは使わない）。
- 受け取りは1回で全部。

## 3. 作ったもの

### 3.1 サーバー（`server/src/domain/goals.ts`、`contracts/protocol.md`「目標の階段」、REQ-GOAL-001〜012）
- `GET /v1/home/goals`：`goalLadderView` — 読むだけ。
  - `today`：デイリー＋今日の初勝利ボーナス（自動で払われるので「受け取り」にはしない）、`done/total/claimable/complete`、`resetAt`（次のゲーム日の始まり）、`loginBonus.next`（今日まだなら今日の、受け取ったら明日のログボ。初心者の7日→7日周期の順で）。
  - `path`：初心者ミッションの今の段・全段数・最後の段の報酬（終わったら null）。
  - `week`：週替わり（クリア数・報酬・バッジ）・ライバル（今週の点・ランク戦の数と結果に要る数・勝った時の額）・支部の共同目標（ルートが渡した時）・**先週のライバルの結果（未読の間）**。
  - `season`：クラス・ポイント・ライン・残り・状態（rookie／climbing／line_reached／top）・**ペース**（自分のこのシーズンの1戦平均、3戦以上の時だけ、何戦で届くか）・**相棒の力**（`raceStats` の合計、いまのクラスで出せる分、次のクラスで出せる分、上限で止まっている分）・クラスの階段（上限・昇級ライン・報酬の一番上の帯と出走した人全員の帯）・シーズンミッション・パスのレベル・§68 の昇級戦（統合後に `extras.promotion`）。
- `POST /v1/home/goals/claim`（Idempotency-Key 必須）：`claimAllGoals` — デイリー・初心者（届いている段を順に）・シーズンミッションを1つのトランザクションで。受け取る物が無ければ 409 `NOT_ELIGIBLE`。KPI `goals_claim_all`（数とコインだけ、§58 `optional`）。メンテナンスの区分は `core`。
- 次にやること：`missions_claim` の件数に初心者の段とシーズンミッションを足す（`NextSummary.extraClaimable`、任意の項目なので古い要約もそのまま）。
- テスト：`server/test/goals.test.ts`（13件：新規・今日・シーズン・相棒の力・最上位・週・明日のログボ・読むだけ・まとめて受け取り＝1件ずつと同じ残高・冪等・初心者の順・次にやることの件数・HTTP とメンテナンスの区分）。

### 3.4 プロトタイプ（`tools/figma-prototype`）
- **ホーム**：左上のシーズン枠 → **目標の階段**（1段 50px、2〜4段。受け取れる段に金の点）。ライバルの帯と週替わりカードは「今週」の段へ。ライバルの週の組み合わせはホームが今まで通り読む（帯が無くなっても組まれる）。メニューの「ミッション」→「目標」（金の点は付けない：階段と次にやることが言うので3つ目は要らない）。お知らせのカード枠は階段の下（y=260）へ、アップデートのお知らせは2件＋「ほかn件」。
- **目標の画面**：3列（今日／はじめの10歩・今週／シーズン）。報酬の下に使い道。シーズンの列に「なぜ上をめざす？」（相棒の力のバー：いま・次のクラス）、「クラスの階段 ›」、シーズンミッション。塗りの CTA は「まとめて受け取る（n件）」の1つだけ。
- **受け取りの瞬間**：中央のダイアログに届いた物を1行ずつ（少しずつずらして浮かぶ、動きを減らす設定ではフェードだけ）。
- **クラスの階段**：S→Cの4段、上限・昇級ライン・報酬の帯、いまのクラスに枠。「買える物で上限は変わりません」。
- 次にやることの「ミッション」の行き先は目標の画面。

## 4. オーナーに決めてほしいこと

1. **パスの無料ライン**（提案6）：「10枚×30段」を「50枚×5段ごと」に（合計同じ）。E5〜E7 は有料ライン側なので動かないはずだが、受け取りの時期がずれるので経済を回してから。
2. **勝利への三重払い**（提案7）：デイリー「1着になる」30枚を「りんごのおやつ×1」などに変えると目標が馬に寄り、E1 に余裕が出る（−30枚/日）。アイテムの E 番号（E15）が動くので数字を見て決める。
3. **パスの無料報酬をまとめて受け取りに入れる**（提案8）：無料プレイヤーを購入画面に送らない代わりに、パスの画面を見る回数は減る。
4. 古い「今日やること」のシート（`Missions()`）はホームから外した。Unity でも `HomeModel.TodayLines` を `GoalLadderModel` に置き換えてよいか。
