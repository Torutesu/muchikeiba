# レース中の操作と駆け引き（race play）— 品質監査とルールセット 1.4.0

品質パスの4本のうち「レース」。オーナーの評価は「レース中の操作と駆け引きが浅い」。ここがゲームの心臓なので、
**1レースの中でプレイヤーが下す判断の数と重さ**を測り、浅い理由を数字で示し、いちばん効く3つの仕組みをエンジンから
HUD・振り返りまで通しで作った。数字はすべて `engine/Muchi.Verifier` のハーネス（固定シード）で再現できる。

- ブランチ：`quality/race-play`
- 触ったところ：エンジン（`Muchi.Engine`）・検証（`Muchi.Verifier`）・クライアント SDK（`Muchi.Client` の RaceFeel / RaceTactics / 入力）・Unity のゲーム層（RaceInput / HudModel / RaceResultModel）・サーバー（ルールセットの切り替え）・プロトタイプのレース画面と結果画面だけ。レース以外の画面と全体の見た目は触っていない（見た目のワークストリームの担当）。

## 0. 結論

1. **1.3 のレースは「ゲートの反射神経」と「手綱を押しておくこと」でほぼ決まり、駆け引きの判断が無い。** 上手い人の乗り方から1つずつ判断を抜くと、スタートを0.25秒遅らせると −1.17秒、手綱を使わないと −1.36秒、ムチを全く使わないと −0.50秒、なのに**風よけの位置取りは +0.01秒（価値なし）**、**ムチの打ち始めを「残り150m」から「残り400m」に変えても差は 0.08秒**（むしろ速い）。スパートは全員同じ地点で自動に始まるので、前半に溜めた脚の使い道が無い。
2. **ムチの長押しを決めた：押して溜め、離して仕掛ける（一閃）。** ムチのボタン1つが、仕掛けの前は「溜め」、仕掛けた後は「ムチ」になる。押している間は馬を抑えて脚を溜め（満タン2秒）、離した瞬間にスパート開始＋溜めた分の加速。新しい入力ビットは使わない（1.4 では発走後の START＝ボタンを離した）。
3. **1.4.0 で入れた3つ：① 仕掛け（いつスパートするかをプレイヤーが決める、金の「持つライン」で見える）② 会心（拍に合わせたムチは強い、ボタンの輪で見える）③ 抜け出し（風よけからの抜け出しで加速）。** 結果：持つラインで溜めて仕掛けると自動の仕掛けより 0.61秒速く、早すぎ（+35%）は 0.74秒・遅すぎ（−35%）は 0.61秒の損（両側に損がある判断）。会心は 0.18秒、溜めは 0.11秒、抜け出しは 0.07秒。**同じ馬なら上手い人が 67% 先着、10%強い馬（550 対 500）には 33%、20%強い馬（600）には 30%** —腕は効くが大きな能力差はひっくり返らない。R1〜R8（R4b を除く）・全コース全馬場の脚質の釣り合い（T1/T2/T7）は 1.4 でも満たす。
4. **振り返りは作り話をしない**：結果画面の「仕掛けがあと0.5秒早ければ2着」は、同じ乗り方で仕掛けだけをずらして端末でエンジンを走らせ直した結果（約10レース）から出す。
5. 既存のルールセット（1.3.0 以前）の結果・ゴールデンは1バイトも変わらない。1.4 は**モードごとの切り替え**（`progression.raceTactics`）で、同梱では練習レースだけ on。検証サーバー → Worker → アプリ（エンジンの水準 2）→ モードを順に（`docs/ops/deploy.md`）。

## 1. 監査：今のレース（1.3.0）

### 1.1 遊んでみた（新規・30日目相当）

プロトタイプ（`index.html?demo=day7`、本物の WASM エンジン）でランク戦を、初めての人のつもりと慣れた人のつもりで何度か走った。スクリーンショット（scratchpad `qrace-shots-before/`）。

- **何をすればいいか分からない時間が長い。** ゲートの後、1分以上やることが無い（手綱と内外のボタンはあるが、押す理由が画面に無い）。合図は残り400mの「今だ、ムチ！」だけ。
- **前が壁なのに「脚をためている」と褒められる。** 1本目は1000mから最後まで11番手で前が詰まったまま（`blocked: true`）だったが、HUD の1行はずっと「脚をためている」（風よけ扱い）。外へ出せという合図は無い。結果画面の敗因は「ムチが遅かった」。実際の敗因（包まれた）と違う。
- **スタートの押し遅れでムチが1本減る。** スタートとムチが同じボタンなので、ゲートが開いた0.5秒後に押すと自動発走の後のムチ（早打ち：効き15%・折り合い−10）になる。1本目で起きた（残り1894mでムチ6→5）。
- **ムチは「最後に間隔をあけて6回」の作業。** 何回か走るとそれ以上の工夫が無いことが分かる。間隔の正解（20tick）は画面に出ない。
- **結果画面は1行の理由とヒント**。どうすれば勝てたかは分からない。

## 2. 決定：ムチの長押し

長く決まっていなかった「ムチを長押ししたら何が起きるか」を、次のとおり決めた。

| 案 | 中身 | 採らなかった理由 |
|---|---|---|
| A 連打の代わり | 押している間、決まった間隔でムチ（今のアクセシビリティ設定の長押し、§41） | 判断も上手さも無い。アクセシビリティの補助としては残す |
| B 追い続ける | 押している間ずっと速くなり、脚を多く使う | 「押しっぱなしが正解」になりやすい。連打の言い換え |
| C 強いムチを溜める | 押して溜め、離すと強いムチ1回 | ムチと仕掛けが別々の判断になり、指が足りない。ムチの本数の勘定が複雑 |
| **D 溜めて、仕掛ける（採用）** | **仕掛けの前は、押すと溜め（馬を抑えて脚を溜める）、離すと仕掛け（スパート開始＋溜めた分の加速＝一閃）。仕掛けた後は普通のムチ** | ― |

**D にした理由**
- **1つのボタン・1本の親指**：ボタンは「溜める→離す→リズムよく叩く」の順にしか使わない。片手のレイアウト（§41）でもそのまま。
- **本物の騎手の技に重なる**：手綱を抑えて脚を溜め、直線で追い出す。題名「ムチ一閃」そのもの。
- **両側に損がある判断**：早く離すと脚が持たず、遅いと伸びきらない。溜めるほど加速するが、溜めている間（最大2秒）は少し遅れ、前が詰まっていれば加速は無駄になる。
- **新しい入力ビットが要らない**：1.4 では発走後の START（bit0）を「ボタンを離した」と読む（1.3 以前では発走後の START は何もしないので、古いレースは変わらない）。
- **補助と両立**：かんたん操作（§27）は溜めず、自動の仕掛け（上手な手より弱い）。アクセシビリティの長押し（§41）は、仕掛けの前は同じく溜め／離して仕掛け、仕掛けた後だけ決まった間隔で繰り返す。

**ルール（1.4.0 の値）**
- 仕掛けの窓：残り ≤ スパート区間 × 2.5（2000m芝で 1750m）。窓より前の押しは今までどおりの早打ち。
- 溜め：押している間、目標速度 95%・消耗 45%（手綱と同じ）。40tick（2秒）で満タン、満タンで自分で仕掛ける（溜めきり）。
- 一閃：仕掛けた瞬間から 30tick、速度 +2.5m/s・加速 +3.0m/s² × 溜め/満タン。
- 仕掛けなければ：スパート区間（2000m芝で 700m）で自動に仕掛ける（1.3 と同じ地点、溜め 0）。
- 早く仕掛けた馬（ロングスパート）は、スパート区間までは最高速（上乗せ 0）。掛かりはスパート区間までは起きうる（早い仕掛けで掛かりを避ける抜け道を塞いだ）。

## 3. 1.4.0 の仕組み（contracts/protocol.md §14.1、REQ-RACE-090〜099）

1. **仕掛けと持つライン**：エンジンが整数で見積もる `GoLineM`（今のスタミナでスパート区間の分とその前のロングスパートの分が足りる位置 × 1.05、窓で頭打ち、自動の地点より遅くはならない）を、HUD は「仕掛けバー」の金の線で、CPU は仕掛けの目安に使う。線の手前（満タンの溜め2秒ぶん）でボタンが金に光り「今：長押し」。
   - 前半の判断の意味が戻る：手綱・風よけで残した脚が線を前に動かす（1.4 では風よけを探さないと −0.0x秒ではなく、線が遅れる）。
2. **会心**：仕掛け・前のムチから 18〜24tick（0.9〜1.2秒）後のムチは効果 1.4倍。ボタンの周りの輪が進み、金の弧に入った時に押す。外すと普通、早すぎると連打の減衰。
3. **抜け出し**：窓の中で 1.5秒以上風よけにいてレーンを変えると、2秒間 速度 +2.0m/s・加速 +4.0m/s²。HUD は「外が空いた：抜け出せ」。包まれている時は「前が壁：外へ出してから仕掛けよう」。
4. **CPU**：全レベルが同じ仕組みを使い、違うのは読みの正確さだけ（レベル5 は線の少し後ろ・満タンで溜める、低いほど遅く・ばらつき大きく・溜めが短い、レベル1 は溜めずにタップ）。逃げ馬は早めに仕掛ける（脚質の釣り合い R2 のため）。ムチの間隔は会心の拍（18tick＋レベルの揺れ）。
5. **公平**：ランク戦で買えるもので強くなるものは無い（クラスの能力上限・スキルの上限はそのまま。ムチ・溜め・会心・抜け出しはどの馬にも同じ）。

## 5. HUD・手応え・実況・振り返り（プロトタイプのレース画面＝本物のエンジン）

- **仕掛けバー**（上の中央、局面の帯の下）：窓の始まり（左）からゴール（右）。今の位置（自分の色の点）、金の持つライン、灰色の自動の地点。仕掛けた後は金で塗られ「会心 n」。
- **ムチのボタン**：局面で文字と輪が変わる。「仕掛ける」→（線の手前で金に点滅）「長押し」→ 押している間は輪が金で満ちる「離す」→ 満タン「一閃」→ 仕掛けた後は「ムチ」と拍の輪（白い進み＋金の弧）。金の弧の中で押すと「会心！」。
- **手応え**：一閃は強い振動＋視野のキック＋「一閃！」、会心は軽2回＋金の「会心！」、溜めきりは中1回、抜け出しは軽3回＋「抜け出した！」、仕掛けどころの合図は弱い3連。動きを減らす設定では点滅しない（色で示す）。
- **1行の合図**（優先順）：掛かり → 溜め中 → 抜け出した／会心／一閃 → 前が壁 → 仕掛けどころ → 抜け出せ → 競り合い → …。**前が詰まっている時に「脚をためている」と言わない**（1.4）。
- **相棒の頭上**：競り合いの相手がいる時は「競り合い　相手の名前」（金）。
- **結果画面**：敗因・勝因の下に金の1行「振り返り：仕掛けがあと0.5秒早ければ2着　·　会心のムチ 3/5」。走らせ直しは約10レース（端末で1秒未満）。行はどれも実際に走らせたレース（`GoCounterfactual`）。ヒントも振り返りに合わせる（「金の線で長押しして溜め、離して仕掛ける」など）。

## 6. 出し方（docs/ops/deploy.md §7.1）

- **検証サーバー → Worker → ストアのアプリ（`EngineInfo.Level` 2）→ モードを順に on**。1.4 のレースは Level 2 の端末だけ（部屋が 4026 で断る）。練習のカタログは `x-engine-level` が 2 の要求にだけ 1.4。
- 同梱の `progression.raceTactics`：練習だけ on。フレンド・カップ（と §66 のキャリア）はアプリが行き渡ってから、ランク戦は 1.4 のフレンド戦を1週間見てから、リモート設定で on。止める時は off（次のレースから 1.3.0）。
- プロトタイプはランク戦・フレンド戦でも 1.4 を先取りで見せる（`MuchiLogic.tactics(false)` で同梱の切り替えに戻る）。

## 7. オーナーに決めてほしいこと

1. **ランク戦の 1.4 への切り替えの時期**（推奨：アプリの配信から2週間・1.4 のフレンド戦で検証の不一致が 0 のまま1週間）。
2. **腕の効き具合**：同じ馬で上手い人が 67%、20% 強い馬には 30%。もっと腕寄り／能力寄りにするなら `goLinePermille`・`kickSpeedBonusMmPerSec`・`rhythmBonusPermille` で調整できる（目標 K6/K7 を先に決める）。
3. **スタートとムチのボタンを分けるか**（Unity の画面。1.4 では窓より前の押しだけが早打ちなので損は小さくなったが、ゲートの押し遅れでムチ1本の損はまだ起きる）。
4. **初心者マッチ（R10）を 1.4 で測り直すか**：CPU も仕掛けを使うので、初心者の3着以内の割合が変わりうる（R10 は自動テストが無い）。ランク戦を 1.4 にする前に測る。
5. **競り合いの専用の仕組み**を足すか（今は演出だけ）。
