# 品質監査：育成・配合の手応え（raising & breeding）

更新：2026-11-12　ブランチ `quality/raising`　対象：調教（§25）・馬ごとの目標（§53）・絆・固有スキル・配合と遺伝（§8.5・隔世遺伝・季節限定馬）・殿堂（§34）・厩舎の整理（§44）

オーナーの評価：「馬を育てても強くなった感じがしない。配合で狙う楽しさが無い。」

## 1. やったこと（監査の方法）

- `bash tools/figma-prototype/build.sh` のあと、本物のサーバーのドメインと WASM エンジンで動く `index.html` を Playwright で遊んだ（1600×900）。
  新規（`?demo=new`）→ 1日目 → 7日目（`?demo=day7`）→ 30日目相当（調教を素質いっぱいまで回したセーブ）。
- 見た画面：厩舎（相棒の詳細）、調教（メニュー → ミニゲーム → 結果）、所属馬の一覧（§44）、馬ごとの目標（§53）、殿堂（§34）、配合（club.html にはあるが `index.html` には無い）。
- 読んだ仕様：`contracts/protocol.md` §8.5・§25・§34・§44・§53、`docs/spec/requirements.md` 25章、`docs/planning/06` §2・§6.7・§7.1、`docs/spec/balance-targets.md` 4.12（E15）。
- 数字はすべて本物のロジックから取った（`server/src/domain/training.ts`・`horses.ts`・`season.ts`）。

## 2. 見つかったこと（弱い順ではなく、効いている順）

### F1. 調教の伸びが「見えない」——画面のどこにも、育った馬が出てこない（最重要）

- 調教の結果は「+6（瞬発+3・スタミナ+2・根性+1）」と大きく出るが、**その馬の画面（厩舎）は `base` しか表示しない**（3能力だけ、しかも ÷10 の 100 点満点表示）。調教で伸びた分（`trained`）は厩舎・所属馬の一覧・馬の目標・殿堂のどこにも出ない。+6 を10回やっても厩舎の「瞬発 72」は 72 のまま。
- 表示の単位もずれている：結果の「+6」は生の能力値（0〜1000）、厩舎は ÷10。仮に伸びを足しても「72 → 72.6」で、目に見えない。
- 調教の画面の左に「+0 / +3 …」は出るが、馬の能力（700 前後）に対してどれだけかが分からない。「強くなった」を測る物差しが画面に無い。

**なぜ効くか**：育成ゲームの核は「数字が上がっていく手触り」と「自分の馬が他と違ってくる感覚」。伸びが見えないと、毎日3回の調教がただの作業（デイリーミッションの消化）になり、D7〜D30 の継続の理由が消える。

### F2. 「ランク戦では意味が無い」と画面が自分で言ってしまう

- 7日目の相棒（SR、能力合計 3,320）は C級の上限 2,800 をすでに超えている。調教の画面は「ランク戦（C級 上限 2,800）では 2,800（上限にそろえます）」と表示する＝**どれだけ調教しても何も変わらない**と読める。
- 実際の正規化（`normalizeStats`）は**合計だけを上限にそろえ、能力の配分（比率）はそのまま残す**。瞬発を伸ばした馬は、上限にそろえた後も瞬発寄りの馬として走る。調教は「合計」ではなく「個性（配分）」をランク戦に持ち込んでいる——のに、それがどこにも書かれていない。
- 課金で買えないことは正しく守られている（E15）。問題は公平性ではなく、伝え方。

### F3. メニュー選びが「どれでもいい」——選択の結果が事前に見えない

- 4つのメニューは「伸び 6・疲れ +30・瞬発・スタミナ・根性」と設定値をそのまま出すだけ。**この馬が今これを選ぶと何点伸びるか**（疲れ・絆・伸びしろで変わる）は、始めて回数を1つ使ってから初めて分かる（start の `preview`）。
- 疲れの罰（1点 5‰）・絆の上乗せ（併せ馬は ×2）・伸びしろの逓減は「内訳」として結果の後に小さく出るだけ。プールで休ませるか、疲れたまま坂路を回すかの判断材料が無い。
- 結果として最適行動は「上から順に押す」で、選択の楽しさが生まれない。

### F4. 成長の「区切り」が無い

- 素質ゲージ（6 / 240）が1本あるだけ。SR の相棒は 1回 +6 前後・伸びしろで遅くなり、素質いっぱいまで 30日以上かかる。その間に「一段階強くなった」と感じる節目（演出・名前・見た目）が無い。
- 30日目には素質いっぱい → 調教のボタンが灰色になるだけ。「完成した」という報酬の瞬間が無い。

### F5. 配合はメインの UI に存在しない（`index.html`）

- サーバーには十分な仕組みがある：能力の幅（±60）、ニックス、近親、脚質・馬場適性・固有スキル・隔世遺伝の確率（どれも実際の抽選と同じ関数）、種牡馬の貸し借り、配合素材。
- しかし `index.html` には配合の画面が無い（厩舎のコメントに「the prototype has no breeding screen」）。club.html の画面は「能力の幅」の表を出すだけで、**どの親が何を渡せるか**、**SR・SSR の仔が生まれる見込み**、**生まれた瞬間の演出**が無い。
- `rarityForTotal`（合計 3,200 で SR・3,700 で SSR）は配合の仔のレア度を決めている＝**配合で SSR を狙える**のに、その確率がどこにも出ない。「狙う」理由が見えない。

### F6. 血統を気にする理由が弱い

- 血統表（§71、別のワークストリームで作成中）はあるが、自分の馬が「何代目」か、スキルが父から来たのか母から来たのか、隔世遺伝で誰の脚質を継いだのかは、生まれた瞬間のトースト1行で消える。
- 殿堂（§34）・目標（§53）・戦績（`career`：ライバルに先着・最大の勝利）は良いデータを持っているのに、**馬の画面にまとまっていない**（殿堂は引退後、目標は左下の小さなパネル）。

### F7. 細かいこと

- 厩舎の詳細は5能力のうち3つだけ（根性・気性が無い）。
- 調教の結果「つづける」で調教の画面に戻るが、伸びた馬の能力がどう変わったかは見えない。
- 所属馬の一覧（§44）は整理のための画面で、育成の画面ではない（並び替えに「調教の伸び」が無いのは仕様どおりで問題ない）。

## 3. 他の強いモバイル育成ゲームが上手くやっていること（一般論）

- **数字が動く瞬間を演出する**：バーが伸びる・前の値から数字が数え上がる・節目で色が変わる。「どれだけ」を毎回その馬の物差しで見せる。
- **選ぶ前に結果の見込みを出す**：メニューごとに「この子なら +5〜+6」と出し、疲れや相性で数字が変わるのを見せる。プレイヤーの判断が数字に反映されるのが分かると、選択が楽しくなる。
- **成長に段階と名前を付ける**：新馬 → 本格化 → 完成のような区切り。段階が上がる瞬間を祝う。
- **配合は「予告 → 期待 → 開封」**：親が渡せるものを並べ、確率は正直に出し、生まれる瞬間は1つずつめくる。期待の幅のどこに着地したか（「期待以上！」）を見せる。
- **馬に物語を持たせる**：戦績・倒したライバル・何代目か・誰から何を受け継いだか、を1枚のカードにまとめる。

（特定の作品の名前・キャラクター・画面の配置・仕組みはまねない。）

## 5. 今回作るもの（1〜3）と守ること

- **ランク戦の公平性**：伸びは課金で増えない（既存の `trainingProblems` のまま）。新しい商品・付与・消費は作らない（E1〜E19 は変わらない）。表示を増やすだけで、レースの結果・ルールセット・ゴールデンは変えない。
- **確率は既存の規則だけから**：配合のレア度の見込みは `horses.ts` の `baseline`・`BREED.variation`・`clampStat`・`rarityForTotal` から厳密に畳み込みで出す（新しい乱数・新しい確率は無い）。調教の見込みは `computeGain`（実際の finish と同じ関数）。
- **コンプガチャ無し**：成長段階・世代は表示だけで、報酬を付けない。
- **§71 の血統表は作らない**（別のワークストリーム）。馬カードは「何代目・誰から何を継いだか」の要約だけ。
- 見た目は自分の画面の中だけ（全体のスタイルは見た目のワークストリーム）。既存の部品（`Glass`・`Kicker`・`Gauge`・`Cta`）を使う。
