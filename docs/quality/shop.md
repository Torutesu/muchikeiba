# 品質パス2：課金の体験（ショップ・スカウト・シーズンパス・受け取り）

ブランチ：`quality/shop`（`origin/main` = 品質パス1 統合後 から）　ログの接頭辞：`q2sh-`
対象：ホーム → ショップ（おすすめ・コイン・見た目・パス）／スカウト／シーズンパス／スターター・昇級記念の案内 → 購入の確認 → めくり・受け取り → 手に入れた物を使う。
目標：遊んで気に入った人が、迷わず・だまされたと感じずに買えて、買った物をその場で楽しめること。

### 1.2 ジャンルの強いゲームがうまくやっていること（仕組みとしての一般論）

- 消費の前に「何を・いくつ使うか」を1行で言い、押すまで何も減らない。
- 買った直後に「届いた物」を1つずつ見せ、**その場で使う一歩**を1つだけ出す（別の商品に誘わない）。
- まとめ売りは合計を足し算で書く（比率や「倍」は使わない）。品物は遊びの中での効き目を一言で。
- 見た目は自分のキャラ・自分の馬で試せる。
- 売り場は「今買える物」だけを並べ、買い終わった物は履歴へ下げる。

## 3. 今回やったこと

### 3.1 スカウトの確認（`GET /v1/gacha/:bannerId/options`、protocol Q2.1）
- サーバー `scoutOptions.ts`：このプレイヤーが今このバナーで引ける方法を全部。コイン（1回・10回、ステップアップは今のステップの価格）は `spend` と同じ順（有償から、有償限定は有償だけ）の内訳 `pays` と引いた後 `after`、足りなければ `shortfall`（§29 と同じ数え方）。**持っている**券（有償限定・ステップアップには出ない）、SR以上確定券（専用の表・天井pt なし）。文はサーバーが作る（「有償コイン300枚と無償コイン700枚を使います」）。読み取りだけ（何も予約しない。引く時にサーバーが改めて判断）。
- 見本：スカウトの画面に券のボタン（「スカウト券で1回引く（2枚）」「SR以上確定スカウト券を使う（1枚）」）。コイン・券どちらも確認のシート：使う物の1行（金）、内訳の帯（有償＝金、無償＝シアン、使う順）、引いた後の残高、天井pt、提供割合（SR以上確定券は券の表）、主ボタン「引く（1,000コイン）」と「閉じる」。足りない時は確認を出さず T6、終わったバナーはサーバーが拒否。券の引きも同じめくり（SR/SSR の溜め）と一覧。
- C# `ScoutOptions`・`ApiClient.GetScoutOptionsAsync`、Unity `ScoutConfirmModel`（`For`／`ForSrTicket`／`RouteFor`：確認・T6・止める、2回目のタップは無視、KPI）。

### 3.2 購入の受け取り（`POST /v1/shop/purchase` → `receipt`、protocol Q2.2）
- サーバー `receipt.ts`：購入の記録から、届いた物（有償コイン・はじめての購入の無償コイン・品物＋効き目・パスの全段とシーズンの終わり・厩舎手当）、今の残高、注意（自動更新なし・履歴の場所）、**使う一歩を1つ**（SR以上確定券 → 使う、パス → パスを見る、厩舎手当 → 今日の分、勝負服の柄 → 着せてみる、コイン → スカウトへ）。別の商品には決して案内しない（テストで確認）。
- 見本：購入の確認の主ボタンが「購入する（デモ・決済なし）」になり、受け取りの画面で終わる（行が順に現れる。動きを減らす設定では一度に）。コイン不足から来た時は今までどおり元の操作へ（今は確認のシートへ）。おすすめの厩舎手当に「今日の分を受け取る」。
- C# `PurchaseResult.Receipt`（`PurchaseReceipt`）、Unity `PurchaseReceiptModel`（行・残高・`TakeNext` → 開く画面、KPI）。

### 3.3 価値を読めるように・おすすめを静かに
- サーバー：`pass_premium` に `total`・`totalLabel`（「30段の合計：無償コイン1,500枚＋配合素材×30」、足し算だけ）、`item` に `purpose`（`products.json` の `display.itemPurposes`。見た目の品は必ず「見た目だけ。ランク戦の能力は変わりません」）。従来の `label` は同じ（古いクライアントはそのまま）。
- 見本：おすすめは今買える物だけ（買った1回限りのパック・未到達の昇級記念は出さない。昇級したらそのクラスのパックが T4 と同じく出る）。カードは2〜4枚で並びを変える。パスのカードは「11月30日 23:59まで（あと12日）」。購入の確認に品物ごとの効き目。パスの画面：合計と「届いている4段は購入後すぐ受け取れます」、勝負服はサーバーの名前（「シーズン限定勝負服の柄『炎』」）と「勝負服に着せてみる」（勝負服エディタでその柄を自分の勝負服に試着）。

### 3.4 守っていること
- 額・確率・価格・付与は何も変えていない（経済 E1〜E20 は同じ。`npm run economy` で確認）。ランク戦の勝率に効く物は何も売っていない（見た目の品は効き目の文でそう書く）。
- コンプガチャなし（集めた報酬は無い）、「倍」・今だけ・残りわずか・お得・通常価格・賭けの言葉なし（サーバー・Unity・見本のテスト）。有償・無償は確認・受け取りの両方で分けて表示。時間は実在の期間だけ、秒の時計はショップのカードから外した（スカウトの一覧の残り時間は従来どおり実際の終了まで）。
- 自分で決める上限（§67）：購入の確認は今までどおり上限を超えると拒否（デモ購入も同じ `purchaseIntent` を通る）。コインで引くことは円の支払いではないので上限の対象外（従来どおり）。
- KPI（§58）：`scout_confirm`・`purchase_receipt`（クライアント、`optional`、数だけ。引いた・買ったはサーバーの `gacha_draw`・`purchase` で `essential` のまま）。クエリは `docs/ops/kpi-queries.md`。
- 英語：サーバーの文は `i18n/en.ts`・`locale-en.json`（`server-en.json` を再生成）、Unity は `ui-en.json`、見本は `proto-en.json`。`npm run l10n:missing` 0。

## 4. オーナーが決めること（提案。値段と商品の組み合わせはオーナーの判断）

1. **パスの有料ラインに山を**：今は30段すべて「無償50＋素材1」。総額（無償1,500＋素材30）を保ったまま、10・20・30段目を見た目（勝負服の色・馬具）にして他の段を少し増やす案。E7（有料ラインの価値÷価格 ≥ 1.5）は見た目の値付け次第なので、`npm run economy` を回してから。
2. **昇級記念パック（¥1,500）**：中身は「コイン1,020（¥1,500 と同じ）＋柄1つ」で、買う理由が柄だけ。案 A：そのまま（昇級の時だけ出るので邪魔にならない）。案 B：柄を昇級の報酬（無料）に移し、パックはやめる（売り場が1つ減る）。
3. **コインのパック8段**（¥160〜¥10,000）：¥800 と ¥2,400 を外して6段に（迷いが減る、年齢の月額上限 ¥5,000/¥10,000 の買える最大の1商品は変わらない）。
4. **1回引きの確認**：今回は1回でも確認を出す（同じ規則の方が分かりやすい）。「1回引きは確認しない」設定を付けるかはオーナーの判断（付けるなら既定はオフ）。
5. **厩舎手当とパスの重なり**：どちらも「毎日／毎シーズンの小さな無償コイン」。おすすめの枠を空けるなら、手当をパスの画面の下に移す案。
