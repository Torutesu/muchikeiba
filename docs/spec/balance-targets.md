# バランス目標と調整結果（ルールセット 1.1.0）

実プレイのデータはまだ無いので、**シミュレーションで測れる目標**を先に決め、それを満たすように調整した。
目標は全てテストで自動チェックする（数値が外れたらCIが落ちる）。

| 対象 | 計測する仕組み | 自動テスト |
|---|---|---|
| レース（R1〜R8） | `engine/Muchi.Verifier/BalanceHarness.cs`（固定シードで約10秒） | `BalanceTests.DefaultRulesetMeetsEveryHarnessTarget` |
| 経済（E1〜E9） | `server/src/sim/economy.ts`（本物の `PlayerService` とマスターデータで90日分） | `server/test/economy.test.ts` |

## 1. プレイヤーのモデル（コードで定義）

| 名前 | 定義（`BalanceHarness.cs`） | 何の代わりか |
|---|---|---|
| 上手い人 `SkilledRider` | ゲートが開いた瞬間にスタート／脚が「残り距離の割合 −100‰」を下回った時だけ手綱／前に馬がいない時は風よけを探して内へ、遅い馬に詰まったら外へ／ムチ6発を最後に使い切るよう間隔20tickで残り約150mから | 操作を理解したプレイヤー |
| 初心者 `CasualRider` | スタートは0〜8tick遅れ（約半分が好スタートを逃す）／手綱で脚を温存しない／ムチは残り250〜600mのどこかから不規則な間隔で／かかった時・詰まった時は半分の確率で遅れて反応／内外の選択は騎手まかせ（自動で内へ） | 始めたばかりのプレイヤー |
| CPU（レベル1〜5） | エンジン内の `CpuBrain`。1.1からレベル1〜3は初心者と同じ癖で走る（`cpuSloppyMaxLevel`） | 対戦相手の穴埋め |

「上手い人」の乗り方は、候補を総当たりして（`rider-sweep`）一番成績の良い組み合わせにした。手綱を早く引きすぎるとむしろ遅く、ムチは残り400mからより最後の150mに集めた方が速い。

### 目標の理由

- **R1 レース時間**：1レース約90秒（企画どおり）。
- **R2 脚質**：どの馬場でも、どの脚質を選んでも「勝ち筋がある」こと。1.0.0では外を回る損が大きすぎて、ダートと芝の硬い馬場で逃げが強すぎた。
- **R3 腕の差**：「腕で勝つ」が柱。上手い人は同じ馬で平均2着ぶん上がり、5%弱い馬でも初心者に8割勝つ。ただし同じ腕なら5%強い馬に3割は勝てる（運と調子の余地を残す）。1.0.0は上手い人が初心者にほぼ100%勝ち、結果が決まりすぎていた。
- **R3c・R5 CPUのレベル**：レベル3は「初心者と同じくらい」。初心者がCPU（レベル3）に負けても平均1着差以内。
- **R4 ムチ**：連打と早打ちは損、間隔をあけて最後に使うのが得。「残り400mから打ち始める」程度の普通の使い方もムチなしより速い（打って損をする体験を作らない）。
- **R6 得意馬場**：得意な馬場では有利だが、勝率が一様の2倍を超えるほど支配的にはしない。
- **R7 枠順**：内枠有利は小さく（4pt以内）。1.0.0は外枠の勝率が内枠の4分の1で、枠順でほぼ決まっていた。
- **R8 能力**：能力は効くが、一番強い馬の勝率は5割未満。

### 1.1.0 で変えたもの

新しい仕組み（ルールセットの任意キー群。**キーが無い1.0.x のリプレイ・ゴーストは今までどおりの結果で検証できる**）：

| キー | 値 | 中身 |
|---|---|---|
| conditionVariancePermille | 25 | **その日の調子**：各馬の最高速をレースごとに ±2.5% 揺らす（シードから決まる。タイムアタックとチュートリアルでは0） |
| autoRailIntervalTicks / autoRailHoldTicks | 10 / 60 | **騎手の自動の内寄せ**：安全な時は10tickごとに1レーン内へ。プレイヤーが内外を操作した後60tickは自動にしない（自分で選んだ進路は保たれる）。スパート区間では動かない |
| cpuSloppyMaxLevel | 3 | レベル3以下のCPUは初心者の癖で走る（スタート反応が遅い、ムチが不規則、脚の温存をしない） |
| cpuStaminaReinMinLevel / cpuRailMinLevel | 1 / 3 | CPUのレベル別の癖（既定は1.0と同じ） |

値の変更：

| キー | 1.0.0 | 1.1.0 | 理由 |
|---|---|---|---|
| laneWidthMm | 1200 | 500 | コーナーで外を回る損を現実的な大きさに（枠順の偏りの主因） |
| spurtDistanceM | 800 | 700 | 差し・追込の末脚が強すぎた |
| spurtSpeedBonusMaxMmPerSec | 6000 | 5000 | 同上 |
| earlyWhipEffectPermille | 300 | 150 | 早打ちが得になっていた |
| whipStaminaCost | 20 | 25 | 同上（35では「残り400mから打つ」がムチなしより遅くなったため25） |
| goingTurfYieldingDrainPermille / SoftDrainPermille | 1040 / 1080 | 1020 / 1040 | 重い芝で逃げが極端に不利だった |
| goingDirtMuddyDrainPermille / SloppyDrainPermille | 1080 / 1060 | 1100 / 1120 | 湿ったダートで逃げが残りすぎた |

ルールセットの値が変わると結果ハッシュが変わるので、`rulesetVersion` を **1.1.0** に上げた。1.0 と 1.0.0 のゴールデンは `contracts/golden/legacy/` に残し、今も同じ結果で検証できることをテストしている。

想定するプレイヤー：毎日ランク戦6回（着順は1〜12の一様＝平均的な腕）、ログボ・デイリーミッション・パスを全部受け取り、コインが1,000貯まるたびに恒常ガチャ10連、天井ポイントが貯まったら即交換。

## 5. わかっている課題

- **使い道の無いアイテム**：`breeding_material`、`gacha_ticket`、`ticket_sr_plus` は、ログボ・ミッション・パスで配られるが、消費する機能がサーバーに無い（ガチャ券で引く、配合に素材を使う、など）。経済シミュレーションでは数えるだけにしている。使い道を作るか配布をやめる必要がある。
- **CPUレベル1〜3の差が小さい**：勝率は 4.4% / 3.2% / 4.3% で、誤差の範囲では単調だが段差が無い。レベル4・5との差（約15%）は大きい。レベル1・2をもっと弱くするなら、癖の強さをレベルごとに変える仕組みが必要。
- **タイムアタックはリモート設定のルールセットを使っていない**：既定のルールセット（＋調子なし）で発行している。ランク戦と同じく有効な設定から作るように直す必要がある（今回の範囲外）。
- 目標値は仮のもの。実プレイが始まったら、KPI（`docs/ops/kpi-queries.md`）の実測で目標そのものを見直す。
