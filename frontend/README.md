# ムチ一閃 / Frontend prototype

横画面の競馬ジョッキーゲーム UI。グリーン・アイボリー・ゴールド、日本語の明朝・ゴシックと、3D相棒モデルを使ったブラウザプロトタイプです。小画面ではレイアウトを積み替えます。

## 起動とビルド

Node 24 を使用します。

```sh
cd frontend
npm ci --cache /tmp/muchi-npm-cache
npm run dev
# 静的サイトの生成
npm run build
```

開発サーバーは 5173 ポートで起動します。上部の画面セレクトで全10画面を確認できます。URL ハッシュの番号は0始まりです。

## 画面と操作

はじめに（規約同意）→ 最後の直線チュートリアル（仕掛けるを4回）→ 相棒の命名 → 初回無料10連スカウト → ホーム。

- ホーム：選択中の相棒、デイリーミッションの進捗と報酬受取、シーズン記録。
- 厩舎：名前検索、レアリティ絞り込み、評価順・名前順、検索結果なし、出走馬の選択。
- 馬詳細：能力・適性・走り方、出走馬選択、名前・血統・覚醒・引退。配合は親選び、予測、確認、誕生と命名。
- 出走登録：コース・参加条件・出走馬、開始前の確認とキャンセル。フレンドコードは数字6桁を検証。
- レース：順位、残り距離、残り脚、折り合い、ムチ残数、内外のレーン移動、操作フィードバック。
- リザルト：上位4頭の着順表、タイム・着差、報酬内訳、受取済み、再出走。
- スカウト：初回無料・通常・10連・チケット、消費確認、1枚ずつ／全開封、重複素材、結果保存、提供割合、ポイント交換。
- ショップ：商品・価格・残高、生年月・同意の確認、未入力／未来の年月／未同意時の無効状態、確認完了。

命名、選択馬、デモ残高、受取状態は localStorage に保存します。デイリーは日本時間の日付で切り替わります。レース報酬は再読込後も重複受取を防ぎ、新しいデモレースの開始時に受取状態をリセットします。

`src/main.js` が画面、`src/details.js` が詳細操作と状態、`src/style.css` と `src/details.css` が共通の見た目、`src/presentation.js` / `src/showroom-renderer.js` が3Dを担当します。デザイン基準と画面別の変更は [design/DESIGN.md](design/DESIGN.md) を参照してください。

## デザイン書き出しと Figma

`design/screens.svg` を Figma にドラッグすると、基本10画面と詳細・状態違い・モバイルを含む60種類を取り込めます。個別 SVG と参照 PNG は `design/screens/`、画面名・サイズは `manifest.json` にあります。

`design/muchikeiba-figma-detailed.zip` は SVG・PNG・取り込み手順・名前付きフレームを作るプラグインのセットです。Figma デスクトップの Plugins → Development → Import plugin from manifest で同梱の manifest.json を選択して実行します。プラグインの Figma 実機動作は未検証です。

## 検証・再生成

開発サーバーを起動し、Playwright と `/usr/bin/chromium` のある環境で実行します。Playwright はアプリ依存関係には含みません。

```sh
node scripts/verify-details.cjs
node scripts/verify-presentation.cjs
node scripts/verify-fallback.cjs
node scripts/export-design.cjs
python3 scripts/package-design.py
npm run build
```

操作検証は初回導線、入力、スカウト、検索、馬選択、出走確認・キャンセル、フレンドコード、レーン操作、残り脚、報酬と再読込、購入確認を対象とします。1440 / 844 / 390px の全10画面で横はみ出しを確認し、ブラウザエラーと保存した馬名の HTML 混入も検出します。

## アート・3Dの再生成

通常の起動は同梱済みの WebP・GLB・フォントを使います。再生成する場合のみ Blender 4.3、Python の Pillow / fontTools / brotli、システムの Noto CJK が必要です。

```sh
# リポジトリのルートから実行
blender -b --factory-startup -t 8 --python-exit-code 1 --python frontend/scripts/build-showroom.py
python3 frontend/scripts/prepare-presentation.py
```

3種類のモデルは同じ解剖形状と馬具の規則から作り、毛色を頂点カラーで描きます。GLB には骨格と走行アニメーションを含みます。ショールームはドラッグ・ピンチ、レースはアニメーションと芝・レール・影の表示に対応します。WebGL 非対応時は静止画へ切り替えます。

3D は遅延読込で、静止画は WebP、フォントは必要字形のみです。書き出しの元になる PNG はビルド中間生成物で、配布版には WebP を使います。Figma 用 ZIP には OTF とフォントのライセンスも含みます。Three.js は MIT ライセンスです。

## 接続範囲

API・Unity・決済・オンライン対戦には接続していません。能力値、着順、報酬、シーズン記録は画面確認用です。スカウト・チケット・覚醒・引退・配合は、既存のサーバードメイン関数をブラウザ内でも使って計算し、所持・出走馬選択へ反映します。実アカウントの変更にはサーバー接続が必要です。購入確認で生年月を保存・送信せず、決済も実行しません。実際の提供割合・年齢別購入条件・命名NGリストの判定は既存ドメインを共用し、購入上限の正式設定は本接続時に確定します。

Unity の3Dアセットは `unity/`、別の全画面プロトタイプとギャラリーは `tools/figma-prototype/` と `tools/figma-gallery/` を参照してください。

### 配布用ビルドの確認

`npm run build` 後、`npm run preview -- --port 4173` を起動し、別のターミナルで `node scripts/verify-build.cjs` を実行します。最初の画面で3Dコードを読み込まないこと、必要時の3Dチャンク・GLB・フォントの読み込み、ショールームとレース、リソース失敗と JavaScript エラーがないことを確認します。

## Creative Atelier 01

`/creative/index.html` または画面上部の「素材一覧」から、背景・ロゴ・操作アイコン・クラス章・アイテム・枠・状態表示・材質・動き・音・告知テンプレートの112点を確認できます。SVG93点のPNG書き出し、Figma用固定色アイコン、白アルファのUnity向けアトラス、17材質のBlenderライブラリを含みます。

[制作・使用ガイド](design/creative/GUIDE.md) と `public/creative/manifest.json` が素材台帳です。原版と生成プロンプトを保管し、背景の推奨文字エリア・sRGB/PBR設定・枠の保護幅・音の音量・reduced-motionの扱いまで記録しています。

`design/creative/muchi-creative-kit.zip` は素材一覧、原版PNG、SVG、派生PNG、編集用告知データ、音、Blender材質、フォント、制作スクリプトの配布セットです。再生成手順はガイドを参照してください。ホーム・スカウト・シーズンパスには新しい背景を適用しています。厩舎の状態表示、馬詳細の装い、報酬トロフィー、通貨にも素材を組み込み、ショップから3色の勝負服プレビューを開けます。

## 初回体験・キャンペーン

初回4章の進捗、1操作ずつの直線ガイド、初勝利の記録とコレクション導線、累積7回の無料ギフト、期間で表示を切り替えるイベント、30日パスの比較、スターターの商品詳細を実装しています。商品・報酬・イベント内容はサーバーマスターを参照します。

[3案の比較・3回の改善記録・計測案](design/campaign/STRATEGY.md) と [画面レビュー](design/campaign/index.html) を参照してください。`node scripts/verify-journey.cjs` で日付境界・受取・商品確認・レスポンシブ表示を検証できます。ログインアイテムはブラウザ内の所持品に反映し、サーバーへ付与しません。購入確認だけでは何も付与せず、続く「この内容をデモで試す」を選んだ場合だけ体験用のセット・パスへ反映します。

## 所持品・装備・レース進行の体験

ヘッダーの「所持品」またはホームの「勝負服を選ぶ」で衣装を試着できます。未所持でも配色を確認でき、入手済みだけ相棒ごとに保存できます。衣装の柄は2Dカード、3Dはモデルの勝負服・帽子・トリムの配色プレビューです。WebGL非対応時は標準装いの静止画と衣装カードを表示します。

実際にデモレースを最後まで走ると1回20XP、100XPでパス1レベルになります。結果画面の閲覧・再読込だけではXPが増えません。無料分・体験用パス分を別々に受け取り、期限と受取済みを保存します。青葉イベントは参加費の確認後に無償30コインを消費し、完走で110pt、累積目標の報酬を受け取れます。通常レースの800コイン報酬とは分けています。

`src/club-state.js` がブラウザ内の受取・所持・装備・レース・パス台帳、`src/club-ui.js` と `club.css` が所持品／試着画面です。旧ギフトの受取記録からアイテムを重複せず引き継ぎます。体験用有償コインは実際の残高ではなく、対戦・ランキング・決済には接続しません。

`node scripts/verify-club.cjs` でギフトから衣装保存まで、任意の商品体験、完走から無料／パス報酬まで、イベント参加費・キャンセル・ポイント・目標報酬・期限、3サイズの9表示を検証します。

## Paddock / 出会いから次の世代へ

スカウトは確認→1枚ずつ／全開封→厩舎まで動き、結果は再読込しても確認できます。有償から先に使用し、残高不足は確定前に表示。通常・SR以上のチケットを所持品から使えます。重複はレアリティ別の覚醒素材、確定枠と提供割合は同じマスターから表示します。初回無料を受け取った後は、常設スカウトを中心としたコンパクトな画面へ切り替わります。

馬詳細の「血統・覚醒・名前と記録」から名前の正規化・NG判定、覚醒、引退ができます。引退は確認チェックが必要で、現役には戻せません。父馬と母馬を選ぶと能力範囲・系統相性・共通祖先を表示。配合前の確認、誕生ビジュアル、命名、厩舎への追加、5代までの血統データを用意しています。日本時間で1日1回。配合では現在のサーバールールどおり素材・コインを消費しません。

`collection.ts` はブラウザ内の所持・操作履歴、`paddock.js` / `paddock.css` は専用画面です。`contracts/master-values.ts` に確率表生成と定数を共通化し、サーバーの抽選・覚醒・配合・血統・命名関数を直接再利用しています。`node scripts/verify-paddock.cjs` で消費・保証・再送・再読込・配合範囲・日付境界・9表示を検証します。

サーバーにも `POST /v1/gacha/tickets/draw` を追加しました。認証と冪等キーが必要で、1枚消費・コイン消費なし・チケット利用でポイント加算なし。実際のストア認証情報・Firebase認証・オンラインレース接続は配備環境の設定が必要です。
