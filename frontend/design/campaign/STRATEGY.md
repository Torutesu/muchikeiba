# 相棒から始まるクラブ体験 / UI提案と反復記録

狙いは、相棒との小さな成功を重ね、欲しい装い・次の仲間・走り続ける楽しみが自然に見つかること。課金率の改善は仮説であり、このローカルデモで売上効果を測定したものではない。

## 比較した3案

| 案 | 体験の中心 | 強み | 懸念・判断 |
| --- | --- | --- | --- |
| A：相棒との最初の物語 | 直線体験→命名→仲間→初勝利→装い | 名前と成功に商品を結び付けやすい。最初にゲームの楽しさが伝わる | 購入までが長いので、ストアには直接アクセスできる。今回の主案 |
| B：コレクションを入口にする | 衣装のビジュアル→内容比較→購入確認 | 外観の好みがはっきりした人に向く | 初見にはゲーム価値が伝わりにくい。ストアと詳細ページに採用 |
| C：レースイベントを中心にする | 開催情報→参加条件→累積目標→次の出走 | 遊ぶ目的があり、継続の理由になる | オンライン対戦は未接続。ブラウザ内の出走・累積・受取まで実装 |

Aを主導線、Bを商品の見せ方、Cを次に遊ぶ理由として組み合わせる。無料ギフトを常設し、購入しなくてもホーム・次のレースへ進める。

## 第1回：情報と導線の構成

- 初回4章をどの画面でも確認できるようにし、ホームへ戻っても「次の一歩」が残る。
- チュートリアルは1操作ごとの短いフィードバック。残り脚と仕掛けるタイミングを説明する。
- 命名で相棒との関係を作り、初勝利後に任意のコレクション導線を置く。
- 商品は「最初のひと揃え」「30日の追加体験」「必要なコイン」の3つの用途で整理する。
- 初稿の実画面を `iterations/store-01.png` と `welcome-01.png` に保存した。

レビューで、内容の理解はしやすい一方、スターターの平面的な衣装アイコンはメインビジュアルとして弱かった。

## 第2回：欲しいと感じる素材とコピー

- 稲妻の勝負服・チケットを主役に、新しいキービジュアルを制作。深緑の布地、金の刺繍、朝の厩舎の光を揃える。
- ストアのセットをフォレスト基調にし、無料ギフト・コインパックと視覚的に区別。価格は最初のボタンにも表示する。
- 衣装・有償コイン・チケットの確定内容を並べ、抽選なのはチケット利用時の馬であることを明記する。
- 無料ギフトは全7回を可視化。3回目の翼の衣装、7回目のSR以上チケットを目標として示す。
- 商品ビジュアルの背景小物は購入内容に含めず、詳細で対象外と明記する。

## 第3回：小画面と判断のしやすさ

- 390 / 844 / 1440pxで実際に表示。モバイルのパス見出しと衣装の重なりを修正し、見出し末尾の一文字だけが次の行に残るコピーも短くした。
- 長いダイアログでも閉じる操作を残し、スターターの価格と確認ボタンを読んでいる位置から使えるようにした。
- 無料／パスを比較表にし、30日・自動更新なし・レベル到達条件をまとめて示す。
- 確認画面は商品IDで取得し、税込価格・有償／無償・各アイテム数を再表示する。誤った生年月と未同意時は次へ進めない。
- 最新の画面は `review/`、Figma向けSVGとPNGは `../screens/` に保存する。

## 仕様とデータの根拠

`src/commerce.js` は `server/master/products.json`、`src/journey.js` は `progression.json`・`events.json`・`tracks.json` を読み込む。マスターを変更しない。

| 内容 | 表示・動作 |
| --- | --- |
| スターター | ¥480 / 有償300 / SR以上チケット1 / 稲妻の勝負服1 / 1アカウント1回 |
| 30日クラブパス | ¥1,000 / 炎の勝負服1 / 購入から30日 / 自動更新なし |
| パス進行 | 1走20XP、100XPで1レベル、上限30。無料は各レベル無償20、プレミアムは追加で無償50と配合素材1 |
| コイン初回特典 | 通常分は有償、同数の初回ボーナスは無償。パックとスターターを区別 |
| ログイン | 50無償→配合素材3→翼の衣装1→100無償→チケット1→100無償→SR以上チケット1 |
| イベント | 青葉スプリント杯の実際のUTC期間をJSTで表示。開始・終了境界に応じて状態を変える |

「連続でなく累積7回、日本時間で1日1回、7回まで期限なし」は今回のUI提案。既存マスターは報酬表のみで継続条件を定義していないため、サーバー接続時にこの仕様の採用を確認する。現在はブラウザ内で受取日と順序を保存し、無償コインのみ既存のデモ残高へ加算する。アイテムはブラウザ内の所持品へ引き継ぎ、重複なく保存する。サーバー所持品へは付与しない。

実決済・オンラインイベントは未接続。ブラウザ内の抽選・覚醒・配合はサーバーの同じ計算を共用する。商品確認だけでは残高・所持を変えない。確認後の明示的な「この内容をデモで試す」で、体験用コイン・アイテム・30日パスをブラウザ内へ反映できる。スターターはデモでも1回のみ。コインパックの初回特典は商品ごとに1回で、体験済みの場合は商品カード・確認画面から追加分の訴求を外す。衣装を相棒ごとに保存し、3Dには帽子・勝負服・トリムの配色を反映する。柄は2Dカードの見本で、3Dの縫製・柄を差し替えるものではない。日程・価格・報酬は既存マスターの暫定値を使っている。

## 次の反復に使う計測案

`muchi-experience-events` は最大200件のブラウザ内ジャーナル。外部送信しない。商品ID・導線・章・日数のみを補足し、馬名・生年月を含めない。

| 問い | イベントと見方 |
| --- | --- |
| 初回でどこに迷うか | `journey_step_complete` の章別到達。実利用時はセッション単位で重複を除く |
| 商品を知りたいと思うか | `offer_view` → `offer_details` → `checkout_open`。ホーム・ストア・初勝利別で比較 |
| 確認画面が分かるか | `checkout_open` → `checkout_preview_complete`。このデモ完了を購入数として数えない |
| 戻ってきたくなるか | `welcome_claim` の実日数別の再訪。連続日数で脱落扱いにしない |
| パスの価値が理解できるか | `campaign_tab` のpass閲覧から商品確認への遷移。価格・期間・無料との差をユーザーに説明してもらう |

実課金率・継続率・満足度は未検証。次のユーザーテストではA/Bの導入コピーを比較し、「商品が何を含むか」「自動更新の有無」「購入しない時の次の行動」が説明できるかを見る。本番計測は決済成功イベント・同意・ID設計を別途実装する。

## 第4回：画面同士をつなぐ（2026年11月7日）

- ギフトのアイテムを所持品へ反映。旧版の受取記録も引き継ぎ、再読込で重複しない。
- 相棒ごとの衣装保存、未所持の試着、入手元への導線、体験コインの表示を追加。3D素材を複製して配色を変え、元のGLB・他の相棒のキャッシュに影響させない。
- 決済確認後の任意操作で商品のデモを試せる。実決済と混同しない「体験用」表示を置き、購入確認のみでの付与を避ける。
- 完走でXPを記録し、無料／パスを別々に受取。画面の閲覧や再読込ではXPを増やさない。パス体験が終わると追加分の受取は停止する。
- イベントは出走確認→開始時の参加費→完走ポイント→目標報酬まで接続。キャンセル時は無償コインを消費しない。通常レースの800コインをイベントへ流用しない。ランキング順位・順位報酬はサーバー接続後の対象とする。
- このブラウザのレースは固定結果の体験版。サーバー権威の購入・所持・競技記録として扱わない。チケット消費・抽選・覚醒・配合も、次の反復でブラウザ内の所持と接続した。

`muchi-club-v1` が所持品、装備、任意の商品体験、受取済みレベル、レースID、完走XP、イベント累積を保存する。実決済の領収書・個人情報は保存しない。

`verify-club.cjs` は、7日ギフトから衣装入手・相棒別保存、商品の任意反映と一度限り、5回完走でLv.1、無料・追加分の再受取防止、イベント3走で330pt、参加費とキャンセル、期間終了をUIから検証する。

Figma用の41〜48は入手済み衣装・レベル到達後・目標到達後を比較するため、隔離した書き出し用ブラウザに明示的なデザインデータを設定している。ユーザーの所持品へ付与する処理ではない。操作の検証は別の実UIテストで行う。

## 第5回：出会い・育成・次世代の操作を完成させる

- 初回無料・通常・10連・チケットの確認画面で、使用するもの、消費前後、重複の扱いを明示。コイン不足・チケットなしは確定前に案内する。
- 開封のカード、1枚ずつ／すべて開く、未開封で戻る、前回の結果、厩舎への追加を接続。表示を閉じても同じ結果が残り、再送で二重消費しない。
- 提供割合は実際の確率表から出し、通常枠・確定枠・レアリティで絞れる。ポイント交換も対象・重複変換・消費前後を確認してから確定する。
- 覚醒は素材の必要数／所持数と、5能力の変化を並べる。引退は戻せないことを確認するチェック付き。最後の現役馬は残すようUIで案内する。
- 引退した牡馬・牝馬を選び、能力の範囲、系統相性、共通祖先、得意距離を予測。日本時間の1日上限を守り、確定前の戻る操作で組合せを維持する。
- 誕生には新しい原版アートを制作。見た目は誕生イメージで、生成された個体の毛色を再現するものではない。カタカナ2〜9文字の命名、半角／ひらがなの正規化、NG判定、後で命名する操作を用意した。
- 詳細の能力は5項目・各1,000に揃え、覚醒・配合予測と同じ単位で表示。馬場適性は芝・ダート・両対応を実データから表示し、固定の芝適性Aを使わない。
- 新しい相棒の能力・名前・性別・血統を保存し、厩舎・詳細・出走馬選択・衣装選択へ反映。モデルは既存3種のイメージを使い分ける。

`contracts/master-values.ts` は既存の提供割合生成を移し、サーバーのexportは維持する。抽選・重複・覚醒・配合予測・配合・血統・命名は既存サーバードメインを再利用しており、見た目だけの別計算を作らない。チケットの消費と抽選は新しいサーバーAPIにも実装し、認証・冪等性・不正なチケット・不足・未精算を検証した。

49〜60のデザイン書き出しは、通常の開封UIと、隔離ブラウザに明示した親の引退・素材所持のデザインデータを組み合わせる。誕生は実際の配合処理を通す。ユーザーの本番所持を操作するものではない。
