# ムチ一閃 — 全画面アプリプロトタイプ（Figma コードレイヤー用）


入口は 2 つです。どちらも同じ本物のロジック（サーバーのドメイン）と本物のレースエンジン（WebAssembly）で動きます。

| 入口 | 中身 |
|---|---|
| `index.html`（クラブ版 UI） | Codex の `frontend/`（緑・アイボリー・金のデザイン）。`frontend/design/screens` の詳細画面 25 枚すべてが、本番の流れの中の画面として動きます。 |
| `unity.html`（Unity 版 UI） | Codex の Unity フロント（`MuchiApp.cs`）を HTML に移したもの。以下の節で説明します。 |

## クラブ版 UI（index.html）

Codex の `frontend/src/main.js`・`details.js` のマークアップとクラス名をそのまま使い、固定のデモデータを本物に差し替えています（`site/club/main.js`）。
スタイルは Codex の `frontend/src/style.css`・`details.css` を `build.sh` が `site/club/codex/` にコピーします（Codex が直すとそのまま反映されます）。

## Unity 版 UI（unity.html）

Codex が作った Unity フロント（`unity/Assets/Muchi/Runtime/MuchiApp.cs`）を、ブラウザでそのまま触れる形にしたものです。
画面ごとの見本を並べたギャラリーではありません。本番と同じ流れで画面が切り替わり、どのボタンも押せます。
Figma にはコードレイヤーとして読み込みます。

- 画面は Unity と同じ 1600×900（CanvasScaler の基準解像度）で、16:9 のまま縮小し、余白は黒帯にします。
- 座標・色・文字サイズは MuchiApp の `Panel` / `Label` / `Button` の値をそのまま使っています。
- 文言は日本語です（`docs/planning/06` §6 の約束どおり、英語の切り替えは「その他」の中）。古い画面は `Localization/ja.json` を使います。
- 画像は Codex の `Resources/Art`、フォントは Noto Sans CJK JP（使う文字だけに絞った woff2）です。

## 画面の流れ（ラウンド8：`docs/planning/06` の REQ-UXP-001〜005）

**はじめての起動（FTUE、REQ-UXP-001）**

タイトル（「同意してはじめる」1ボタン＋規約・プライバシーへのリンク、同意の版と時刻を記録）→ 初レース（400m、**ムチボタンだけ**。残り300mでボタンが光り「今だ、ムチ！」）→ 勝利画面「差し切った！」（ムチ0〜1回なら「おしい！1/2馬身差の2着」→「もう一度」、3回目は必ず勝つ）→ 命名（**乗った馬そのもの**に名前。候補3つ＋自由入力、NG はその場で表示）→ 相棒の確定（自動で進む）→ 入厩祝いの無料10頭スカウト → 1枚ずつめくる（レア度は色＋形＋文字、「すべてめくる」で一覧）→ 2戦目の案内 → 2戦目（青葉 芝1600m・12頭・初心者マッチ）→ 結果（勝因・敗因の1行）→ 3着以内なら通知の前置き → ホーム

- 初レースは `OfflinePresets.TutorialRace`＋`TutorialDirector`（REQ-UXS-004、ライバルはゲート2＝slot 1）。勝ち負けの判定はエンジン側で、画面は結果を表示するだけです。
- 2戦目以降のレースは、サーバーの `buildRaceConfig`（初心者マッチの CPU の強さ、クラスの能力上限、その日の馬場、CPU の固有スキル）で作った出走設定を WebAssembly のエンジンで走らせます（`MuchiRace.StartConfig`）。

**ホーム（REQ-UXP-002）**：① 相棒（名前・絆・調子・固有スキル）② 「レースへ」（右下・最大）③ 今日やること（ログボ自動受け取り・デイリー・初勝利ボーナス）④ シーズン（クラス・昇級まで）⑤ 下部タブ（ホーム／厩舎／スカウト／ショップ／その他）。開放前の機能は鍵と「あと◯戦 か ◯日目で開放」（サーバーの `unlocks`）。
「その他」→「デモ状態」で **初日／3日目／7日目** に切り替えられます（同じ規則のまま日付を進め、毎日ログボを受け取り、レースを精算します）。`unity.html?demo=day1|day3|day7|new` でも開けます。

**ショップ（REQ-UXP-003）**：タブ（おすすめ／コイン／見た目／パス）。所持は有償・無償を分けて表示。商品の中身・初回ボーナス・注意書きはサーバーが作った文言（`shopProducts`）をそのまま表示し、「倍」は使いません。スターターは期限なし（実在しない残り時間は出さない）、パスは実際のシーズン終了までのカウントダウン、昇級記念パックは到達クラスまで鍵、厩舎手当は期間と自動更新なしを表示。下部に特商法・資金決済法・有償コインの使用順。
購入確認は4状態：**未登録**（生年月だけを聞く）／**登録済み**（初回の無償上乗せ、今月の残り上限）／**18歳未満**（保護者同意のチェックはこのときだけ）／**上限超え**（今月の残り金額と翌月1日に戻ること）。アカウント削除の手続き中は購入と案内を止めます。スターターの案内（T2）は結果画面を閉じた後に1回だけ。

**シーズンパス（REQ-UXP-004）**：`passView` の値だけで描きます。レベルと「次まで◯XP＝あと◯戦」、全30段の無料ライン／有料ライン（パス・パス＋）／パス＋（購入時 Lv+10）を横スクロールで。受け取れる段を強調、「まとめて受け取る」、期間は「◯月◯日 23:59まで・自動更新なし」。

**レースHUD・結果（REQ-UXP-005）**：左上に残り距離と脚（30%黄・10%赤点滅・0「脚が上がった」）、右上に順位（発走前は「—」）、左手に内へ／外へ、右手にムチ（発走前はスタート、合図の間だけ光る、残りは数字と点）と手綱（長押し、掛かると赤く光る）、右端に全頭の縦の位置（相棒は大きい点）、相棒の頭上マーカー（勝負服の色＋白縁、ミニゲージ、「前と1馬身」、風よけ中は風の線と「脚をためている」）、固有スキルのカットイン（ルールセット 1.3.0 のエンジンの Skill イベント）、下中央に実況1行。カメラは `RaceCameraRig`（直線で低く寄り、ゴールで横から）。
結果は ① 着順（大）② 勝因／敗因の1行とヒント（`RaceDebrief`）③ 報酬（コイン・シーズンpt・パスXP・デイリー）④ 着順表（相棒の行を強調、着差）、主ボタンは「もう一度」。

その他：厩舎・衣装・競馬場・レース条件・お世話は以前の画面のままです。状態は `localStorage` に残るので、再読み込みしても続きから遊べます（最初からは「その他」→「最初から」）。

## 本物のロジックと、端末だけで動かしている部分

| 部分 | 中身 |
|---|---|
| レース | **本物のエンジン**です。`engine/` の C# と、Unity のゲーム層（`Assets/Muchi/Game`：RaceFactory・RaceInput・RaceDrivers・HudModel・CommentaryFeed・CourseFrame）を .NET 8 で WebAssembly にしたものを動かしています（`engine-wasm/`）。ゴールデンレース 4 本の結果ハッシュが C# 版と一致することを `build.sh` で毎回確認します。 |
| レースの 3D 表示 | `RaceWorld.cs` を three.js に移したものです。<br>・コースは本物のコース形状（TrackGeometry → CourseFrame、ゴール z=420）<br>・スタンド・ゴール板・空・霧・日差しも RaceWorld と同じ値<br>・Codex の FBX 相棒モデルに PartnerGallop と同じ脚の動き<br>・追いかけカメラも RaceWorld.Present と同じ（FOV 57、後ろ 6.5m・上 3m、前方 9m を注視） |
| HUD・実況・結果 | Unity の HudModel（RaceFeel）・CommentaryFeed・RaceResultModel（RaceDebrief）・RaceCameraRig の出力をそのまま表示します。 |
| 操作 | ←/→ で進路、E で仕掛け（ムチ）、Space 長押しで手綱。画面のボタンでも操作できます。 |
| スカウト・命名・ショップ・パス | **本物のサーバードメイン**です。`server/src/domain` を esbuild でブラウザ用にまとめています（`logic/entry.ts` → `site/js/logic.js`）。<br>・ガチャの ppm 表、10 連の保証、天井<br>・提供割合（抽選と同じデータから表示）<br>・名前はカタカナ 2〜9 文字で、ひらがなはカタカナに変換、NG ワードは弾く<br>・同意の記録、相棒の付与、機能の開放、ログボ・ミッション・初勝利ボーナス<br>・商品の表示データとオファー、年齢確認（購入意思の確認）、シーズンパスの受け取り、アカウント削除 |
| 端末だけの部分 | ・保存先はサーバーではなくブラウザの `localStorage`<br>・プレイヤー ID は固定で `local`<br>・開始時に無償コイン 1,200 を付与（1 回だけ）<br>・購入は確認画面まで（**課金処理はしません**）<br>・レースは端末内で走るので、レーティングは動きません（コイン・シーズンpt・パスXP・ミッションはサーバーと同じ規則で精算）<br>・デモ状態（3日目・7日目）は日付を進めた時計で動かしています<br>・衣装・コースの見た目・お世話は Unity 版と同じく端末内の設定です |

## 作り直し方

必要なもの：Node 22、.NET 8 SDK（`wasm-tools` ワークロード）、Python 3 と Pillow・numpy・fontTools。

```bash
dotnet workload install wasm-tools
```

```bash
tools/figma-prototype/build.sh
```

`build.sh` が行うこと：

1. ロジックをバンドル
2. エンジンを WebAssembly に変換
3. 素材をコピー（画像の縮小、相棒の切り抜き、FBX モデル、フォントの絞り込み）
4. ロジックとエンジンのテスト（`test/round8.test.mjs`：チュートリアルの勝ち条件、デブリーフ、固有スキル、ショップ・パス・同意・削除）
5. Round 9 のスカウトのテスト（`test/round9-gacha.test.mjs`：開催カレンダー・天井の表示と持ち越し・ステップアップ・終了の境目。めくりの順・一覧・残り時間は Unity のゲーム層の `GachaRevealModel` / `BannerListModel` を WebAssembly で動かしたもの）

生成物（`site/js/logic.js`、`site/engine/`、`site/art/`、`site/data/`、`site/fonts/`、`site/models/`）は git には入れません。three.js（MIT）は `site/vendor/three/` にそのまま入れてあります。

確認用のコマンド：

```bash
node tools/figma-prototype/test/e2e.cjs
```

```bash
node tools/figma-prototype/test/render-design.cjs unity/design/figma-screens tools/figma-prototype/.compare
```

```bash
python3 tools/figma-prototype/test/compare.py . tools/figma-prototype/.screens tools/figma-prototype/.compare
```

- 1 本目は Chromium でクラブ版（25 画面＋モバイル、`club-*.png`）と Unity 版を通しでクリックします。コンソールエラーが 0 件であることを確認し、画面写真を `.screens/` に保存します。
  Unity 版（`test/unity-flow.cjs`）は横持ちのスマホ（844×390、2倍）で、新規プレイヤーとして FTUE を操作し、各段階までの時間とタップ数を `.screens/ftue.json` に書き、§2.3 の目標（aha 30秒以内・初ガチャ 1分40秒以内・ホーム 4分以内・15タップ以内）を確かめます。タップの前に 0.8 秒の「読む時間」を入れています。画面写真の撮影時間と、描画が実時間より遅れた分（GPU の無い CI 用の計測補正）は時間から除きます。その後、全画面と状態を `u-<番号>-<名前>.png` に撮ります。`E2E_ONLY=unity` で Unity 版だけ回せます。
- 2 本目と 3 本目は、Codex の `frontend/design/screens`（クラブ版）と `unity/design/figma-screens`（Unity 版）と並べた比較画像を `.compare/cmp-*.jpg` に作り、画素の差を数値でも出します。

手元で動かすときは、`site/` を静的サーバーで配信します（WebAssembly を使うので `file://` では動きません）。

```bash
python3 -m http.server -d tools/figma-prototype/site 8080
```

## Figma への読み込み

`build.sh` のあとの `site/` 一式（約 33MB、圧縮後は 40MB 未満）を Figma のコードレイヤーとして読み込みます。入口は `index.html`（クラブ版）で、ツールバーから `unity.html` に移れます。
フレームは 16:9（例：1600×900 または 1280×720）にしてください。中の画面は自動で拡大縮小します。
1 つの HTML ファイルにまとめたものはありません（WebAssembly のエンジン・FBX・フォントを含むため、`site/` フォルダーをそのまま読み込みます）。

## Codex のデザイン画（figma-screens）との違い

デザイン画は完成イメージの一枚絵です。このプロトタイプは Unity の実装（MuchiApp）に合わせています。そのため、次の点が違います。

- ホームのメニュー配置や、ボタンの斜めの形など、MuchiApp 側でまだ実装されていない装飾があります。
- レースは、デザイン画の写真のような背景ではなく、RaceWorld の 3D 表示です（箱でできたスタンドと単色の空）。
- 結果画面には、実際の着順の一覧を足しています。
